# Публикация приложения на GitHub Pages

Инструкция для локального агента (или человека) с правами на репозиторий
`IanGor/Listik`. Результат: приложение открывается по адресу
`https://iangor.github.io/Listik/`, обновляется при каждом пуше в `master`.

Почему так: код приходит с GitHub Pages, а данные лежат на своём сервере
синхронизации ([../server/DEPLOY.md](../server/DEPLOY.md)). Взлом одного
места не даёт одновременно подменить код и прочитать данные.

## Что уже есть в репозитории

- `.github/workflows/pages.yml`: сборка (`npm ci`, проверка типов, unit‑тесты, `npm run build` с `BASE=/Listik/`) и публикация через `actions/deploy-pages`. Запускается на пуш в `master` и вручную (`workflow_dispatch`).
- `vite.config.ts` читает `BASE` из окружения: локальная сборка по‑прежнему с `/`.
- Service worker и манифест используют относительные пути, поэтому работают под `/Listik/`.

## Шаги

1. **Влить ветку с работой в `master`.** Работа лежит в ветке `ccr-7213adeb-mwox5h` (четыре коммита поверх `92144a8`). Если история `master` не ушла вперёд, достаточно fast‑forward:
   ```sh
   git fetch origin
   git checkout master
   git merge --ff-only origin/ccr-7213adeb-mwox5h
   git push origin master
   ```
   Если `--ff-only` отказывает, слить обычным `git merge` и разрешить конфликты (их не ожидается: ветка менялась только здесь).

2. **Включить Pages с источником «GitHub Actions».** Workflow пытается сделать это сам (`configure-pages` с `enablement: true`), но стандартному токену может не хватить прав. Тогда вручную: на GitHub → репозиторий → **Settings → Pages → Build and deployment → Source: GitHub Actions**. Больше ничего выбирать не нужно.

3. **Запустить публикацию**, если пуш в `master` не запустил её сам: **Actions → Pages → Run workflow**. Дождаться зелёного статуса; в задаче `deploy` будет ссылка на страницу.

4. **Проверить.**
   - Открыть `https://iangor.github.io/Listik/` — должен открыться пустой документ с одним пунктом.
   - В адресной строке Chrome появится значок «Установить»; на iPhone/iPad — Safari → «Поделиться» → «На экран „Домой“»; на Android — меню Chrome → «Установить приложение».
   - Открыть меню «⋯» → «Синхронизация между устройствами…» и убедиться, что диалог открывается.

5. **Разрешить этот источник на сервере синхронизации.** В `/etc/listik/sync.env` на сервере должно быть `LISTIK_ORIGINS=https://iangor.github.io` (это уже заложено в инструкции сервера). Без этого браузер не пустит запросы к серверу.

6. **Первое подключение.** На первом устройстве: меню → Синхронизация → «Новый документ на сервере», адрес сервера (например `https://sync.example.com`) и пароль. Код документа из диалога и пароль нужны остальным устройствам («Подключиться к существующему»).

## Если имя пользователя или репозитория другое

Адрес Pages — `https://<владелец>.github.io/<репозиторий>/`. Тогда в `.github/workflows/pages.yml` заменить `BASE: /Listik/` на `/<репозиторий>/`, а в `LISTIK_ORIGINS` на сервере указать `https://<владелец>.github.io`.

## Что сообщить обратно

1. Адрес опубликованного приложения.
2. Статус workflow Pages (ссылка на успешный запуск).
3. Подтверждение, что страница открывается и ставится как приложение хотя бы на одном устройстве.
