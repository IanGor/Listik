# Electron и темы Omarchy: план реализации

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** Устанавливаемый Listik открывает существующий сайт в Electron и всегда следует теме Omarchy.

**Architecture:** Отдельный каталог `desktop/` содержит основной процесс, изолированный preload и упаковку. Основной процесс читает палитру; веб-приложение получает ограниченный протокол v1 и преобразует цвета в существующие CSS-токены. Веб-сборка не включается в пакет.

**Tech Stack:** Electron/Chromium, Node.js, TypeScript/SolidJS/Vite, Vitest, Playwright, Arch PKGBUILD.

**Spec:** `docs/superpowers/specs/2026-11-05-omarchy-desktop-design.md` (согласован пользователем 2026-11-05).

## Global Constraints

- В Omarchy приложение всегда следует его теме. Ручного выбора встроенной темы в этом режиме нет.
- Обычная веб-версия и PWA сохраняют нынешнее поведение тем.
- Новая установка получает данные через существующую синхронизацию с сервером.
- Новая сборка не должна принудительно перезагружать открытый редактор.
- У сайта нет Node.js, произвольного IPC, доступа к файлам или командам.
- Работа в master по правилам проекта; не публиковать и не устанавливать пакет без отдельного поручения.

## Review Focus

- Каталог темы полностью заменяется: наблюдение должно пережить несколько смен подряд (задача 1).
- Файл исчез или повреждён между заменами: не сбрасывать принятую палитру (задача 1).
- Общий origin GitHub Pages: соседний проект и вложенный документ не получают мост (задача 2).
- Новая веб-версия встречает старую оболочку или неизвестный протокол: безопасное поведение без потери данных (задача 3).
- Первый запуск без сети и запуск после кеширования: понятная ошибка либо рабочий редактор соответственно (задача 4).

## Структура файлов

- `desktop/package.json`, `desktop/package-lock.json`: независимые зависимости и команды оболочки, вне сборки сайта.
- `desktop/main.cjs`: жизненный цикл приложения, постоянный профиль, окно и IPC.
- `desktop/preload.cjs`: ограниченный мост v1, без сторонних зависимостей.
- `desktop/omarchy.cjs`: чтение TOML и наблюдение активной темы.
- `desktop/policy.cjs`: проверка URL, отправителей IPC и внешних ссылок.
- `desktop/error.html`: локальная страница ошибки первого запуска с повтором.
- `desktop/packaging/PKGBUILD`, `desktop/packaging/listik.desktop`, `desktop/packaging/listik`: рецепт пакета, ярлык, запуск.
- `src/view/omarchy.ts`: проверка протокола и вычисление CSS-палитры.
- Изменения: `src/view/theme.ts`, `src/view/Menu.tsx`, `src/view/GoTo.tsx`, `index.html` — раннее применение темы и запрет ручного выбора.
- Проверки: `desktop/tests/*.test.cjs`, `tests/omarchy.test.ts`, `e2e/omarchy.spec.ts`, `desktop/tests/smoke.cjs`.

## Задача 1: чтение и наблюдение палитры

**Interfaces:** `readTheme(root): Promise<ThemeState>`; `watchTheme(root, listener): () => void`. `ThemeState = {version: 1, managed: boolean, palette: null | {mode: 'light'|'dark', colors: Record<string,string>}}`. `managed` остаётся true при временном сбое Omarchy. Цвета допускаются только в нормализованном шестнадцатеричном формате; отсутствие обязательных background/foreground отклоняет снимок.

- [x] Написать Node-тесты для светлой/тёмной палитры, отсутствующего mode, старого light.mode, некорректных цветов, исчезновения файла и двух последовательных замен каталога. Проверить сохранение последней корректной палитры.
- [x] Запустить `node --test desktop/tests/omarchy.test.cjs`, подтвердить падение до реализации.
- [x] Реализовать модуль с TOML-парсером: основной путь `~/.local/state/omarchy/current/theme`, совместимый старый путь `~/.config/omarchy/current/theme`. Наблюдать родительский каталог, повторно читать после замены; ограничить размер файла и объединять пачки событий. Закрытие watcher отменяет таймеры.
- [x] Повторить тесты; ожидается PASS. Проверить чтение текущей темы этой машины без записи в её настройки.

Начальный снимок доступен синхронно в preload до исполнения страницы; обновления идут отдельным каналом IPC. Протокол не принимает файловых путей или команд.

## Задача 3: палитра и поведение веб-интерфейса

Для производных цветов проверить контраст основного и вспомогательного текста не ниже 4.5:1 на их фоне; декоративные линии не обязаны иметь такой контраст.
