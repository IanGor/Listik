# Listik — архитектура MVP

Outliner в стиле Workflowy: один бесконечный bullet-список. Главная фича — мгновенная фильтрация по `#tag` на документе объёмом «Война и мир» и больше.

## 1. Требования и бюджеты

**Функции MVP:** добавить / удалить / редактировать bullet, вложить (Tab), вынести (Shift+Tab), подвинуть вверх/вниз, свернуть/развернуть, undo/redo, клик по `#tag` → фильтр.

**Объём.** «Война и мир» ≈ 3 млн знаков. Если бить на bullet'ы по абзацам, выйдет ~25 тыс., по предложениям — ~150 тыс. Целевой бенчмарк: **200 тыс. bullet'ов, 5 млн знаков, глубина до 20**. Запас прочности: 1 млн bullet'ов, если понадобится, переходим на struct-of-arrays (см. §9).

**Сценарий роста.** Такой объём набирается постепенно, внутри приложения, за месяцы и годы. Массовая вставка всего текста разом — не сценарий. Требование другое: когда документ дорос до этого размера, всё должно работать так же быстро, как на пустом. Это ввод и структурные правки, фильтр по `#тегу`, поиск по тексту, запуск и сохранение. Поэтому стоимость каждой операции не должна зависеть от размера документа (или зависеть очень слабо). Сохранение пишет только изменения, а не весь документ.

| Операция | Бюджет |
|---|---|
| Операция | Бюджет | Факт: 67 тыс. (≈ «Война и мир») | Факт: 200 тыс. |
|---|---|---|---|
| Нажатие клавиши: работа (обработчик + вёрстка), p95 | < 16 мс | 1,1 мс | 1,7 мс |
| Enter / Tab: работа, p95 | < 16 мс | 3,6 / 2,4 мс | 4,7 / 4,8 мс |
| Клик по `#tag` → кадр | < 50 мс | 18 мс | 32 мс |
| Ввод в поиск → результат на экране | < 50 мс + кадр | 29 мс | 53 мс |
| Холодный старт: первая строка на экране | < 1 с | 324 мс | 666 мс |
| Память: документ + индексы | < 200 МБ | 50 МБ | 91 МБ |
| Самая долгая пауза главного потока при пересборке снимка | — | 4,5 мс | 4,4 мс |

Все бюджеты выполнены (`npm run bench`, полные таблицы — в `bench/RESULTS.md`).

**Память на 200 тыс. bullet'ов:**

| Часть | Память |
|---|---|
| Документ | 63 МБ |
| Строки и теги | 3 МБ |
| Копия текстов для поиска | 24 МБ |
| **Итого** | **91 МБ** |

Прежняя цифра 188 МБ была ошибкой замера: бенчмарк держал в куче и сгенерированный документ, и только что записанный в IndexedDB снимок. Попутно найдена настоящая утечка, она исправлена: V8 отдаёт длинные строки из `JSON.parse` срезами исходной строки, поэтому каждый текст и id держал весь 26-мегабайтный снимок. Копирование строк при загрузке (`src/util/own.ts`) сократило документ со 113 до 63 МБ ценой ~70 мс загрузки.

**Платформа:** веб (PWA), данные только локально. Модель операций спроектирована так, чтобы синхронизацию можно было добавить позже.
**Стек:** TypeScript + SolidJS + Vite, Vitest для тестов.

## 2. Главные принципы

1. **Модель отделена от реактивности.** 200 тыс. узлов не кладём в Solid store (прокси слишком дорогие). Документ — обычные JS-объекты в `Map`. Solid видит только узкие сигналы (§6).
2. **В DOM только видимое.** Дерево разворачивается в плоский список видимых строк, и рендерится только окно вокруг viewport (~50–100 строк).
3. **Все изменения — операции.** Любая мутация — это `Op`. Операции нужны для undo/redo, для журнала на диске и, в будущем, для синхронизации.
4. **Индексы обновляются инкрементально.** Правка одного bullet'а стоит O(длина его текста), а не O(весь документ).

```
┌──────────────── view (Solid) ─────────────────┐
│ Outline → Virtualizer → Row (static | editing)│
│ keymap.ts → commands                          │
└───────────────▲───────────────────┬───────────┘
   сигналы      │                   │ commands
┌───────────────┴───────────────────▼───────────┐
│ model: Doc ◄─ ops ─ commands       history    │
│        │                                      │
│        ├─► TagIndex (Map<tag, Set<id>>)       │
│        └─► VisibleRows (flat pre-order list)  │
└───────────────────────┬───────────────────────┘
                        │ ops (batched)
┌───────────────────────▼───────────────────────┐
│ persist: IndexedDB = snapshot + op-log        │
└───────────────────────────────────────────────┘
```

## 3. Модель данных

```ts
type NodeId = string;            // nanoid, глобально уникален (задел под синк)

interface OutlineNode {
  id: NodeId;
  parent: NodeId | null;         // null только у невидимого root
  children: NodeId[];            // упорядочены по order
  order: string;                 // fractional index среди соседей
  text: string;                  // plain text, без разметки
  collapsed: boolean;
  tags: string[];                // кэш parseTags(text), lowercase
  created: number; updated: number;
}

class Doc {
  nodes: Map<NodeId, OutlineNode>;
  root: NodeId;
}
```

- **Невидимый root.** Все bullet'ы верхнего уровня — его дети. Тогда не нужны особые случаи «нет родителя». Второй скрытый корень — корзина `TRASH` (§7и): удалённые пункты живут там до компакции.
- **`children[]` в памяти + `order` на диске.** Массив даёт O(1) доступ к соседу и быстрый обход. Строка `order` (fractional indexing) позволяет вставить элемент между двумя соседями, не перенумеровывая остальных. Синхронизации это понадобится. `splice` в массиве даже на 10 тыс. детей — микросекунды.
- **Текст без разметки.** Теги, а в будущем ссылки и даты, — производные от текста и вычисляются парсером. Так проще хранение, undo и поиск.

## 4. Операции, команды, undo

**Ops** — атомарные и обратимые:

```ts
type Op =
  | { t: 'insert'; parent; node: NodeSnapshot }   // поддерево целиком
  | { t: 'remove'; parent; node: NodeSnapshot }   // снимок удаляемого поддерева
  | { t: 'setText'; id; from: string; to: string }
  | { t: 'move'; id; from: Position; to: Position }
  | { t: 'setCollapsed'; id; from: boolean; to: boolean };
```

Каждая операция несёт и старое, и новое состояние, поэтому `invert(op)` обходится без документа: `insert` ↔ `remove`, у остальных меняются местами `from` и `to`. `Doc.apply(op)` — единственное место, где меняется `Doc`. Если `from` не совпадает с текущим состоянием, операция отклоняется. Подписчики (`VisibleRows`, позже `TagIndex` и хранение) получают каждую операцию, а `transact()` объединяет пачку в один commit и при ошибке откатывает уже применённое.

**Commands** — пользовательские действия, каждое возвращает пачку ops (`Op[]`):

| Клавиша | Команда | Семантика (как в Workflowy) |
|---|---|---|
| Enter | `split` | Делит текст по позиции каретки. Каретка в начале → новый пустой bullet выше. Есть развёрнутые дети → новый bullet становится первым ребёнком |
| Backspace в начале | `mergeUp` | Пустой bullet удаляется, в том числе первый в списке или под заголовком zoom (тогда курсор — в конец заголовка, `Outliner.mergeUp`; последний пункт документа остаётся). Непустой склеивается с предыдущей видимой строкой, если у текущего нет детей; у первой строки склеивать не с чем |
| Ctrl+Shift+Backspace | `delete` | Удалить bullet с поддеревом |
| Tab | `indent` | Стать последним ребёнком предыдущего соседа. Нет соседа выше → no-op |
| Shift+Tab | `outdent` | Стать следующим соседом родителя. Нижние соседи остаются у старого родителя |
| Alt+Shift+↑/↓ | `moveUp/Down` | Поменяться местами с соседом. На краю — перейти в конец/начало соседнего «кузена» |
| Ctrl+↑/↓ | `collapse/expand` | — |
| ↑/↓ | фокус | Переход на соседнюю видимую строку, когда каретка на первой/последней визуальной строке |
| Ctrl+Z / Ctrl+Shift+Z | undo/redo | — |
| Esc | — | Сбросить фильтр |

**История** (`src/model/history.ts`): стек пачек операций, до 1000 шагов, только на время сессии. Undo применяет обратную пачку в обратном порядке, redo — исходную. Каждая команда — один шаг. Набор текста (`Outliner.type`) склеивается в один шаг на слово: нажатия продлевают открытый шаг, пока пауза < 1 с и предыдущий текст не кончается пробелом. После undo/redo открытый шаг закрывается. Курсор после undo/redo: для правки текста — в конец изменённого участка, для команд — туда, где команда была вызвана (`before`) или куда она перевела фокус (`after`). Клавиши Ctrl/Cmd+Z, Ctrl/Cmd+Shift+Z и Ctrl/Cmd+Y распознаются по физической клавише (`e.code`), поэтому работают и в русской раскладке. Нативное undo contenteditable перехватывается через `beforeinput` (`historyUndo` / `historyRedo`).

**Многострочная вставка** — одна пачка операций, один шаг undo и одна запись на диск. Каждая строка становится отдельным bullet'ом. Типичный размер вставки — от нескольких до сотен строк. Отступы в тексте (табы, пробелы, `- `) пока не превращаются в вложенность.

## 5. Отрисовка: видимые строки и виртуализация

**VisibleRows** — плоский pre-order список `{id, depth}`. Корень не входит, свёрнутые поддеревья пропускаются, в режиме фильтра остаются только узлы из keep-set. В pre-order поддерево всегда занимает непрерывный отрезок, поэтому структурные операции обновляют список точечно:
- `create` / `delete` / `collapse` → `splice` одного отрезка;
- `indent` / `outdent` → меняется `depth` у отрезка (позиции те же);
- `move` → два отрезка меняются местами.

Полный пересчёт делаем при смене фильтра и при загрузке. Это O(видимых узлов), на 200 тыс. ≈ 5–10 мс.

**Виртуализатор пишем сам** (~200 строк), потому что фокус, каретка и скролл здесь — ядро продукта:
- Высоты строк разные (длинный текст переносится). Измеренные высоты кэшируются в `Map<id, px>`, для неизмеренных берётся оценка.
- Префиксные суммы высот хранятся в дереве Фенвика. И смещение строки, и строка по `scrollTop` находятся за O(log n). Изменение высоты одной строки — тоже O(log n).
- Высота измеряется через `ResizeObserver` на отрисованных строках.
- Якорь скролла: если меняется высота строки выше viewport, корректируем `scrollTop`, чтобы содержимое не прыгало.
- `scrollToRow(i)` нужен для фокуса при ↑/↓ и после команд.

**Строка (`Row`) работает в двух режимах:**
- **static** (все строки, кроме фокусной): обычный `<div>`, теги отрисованы как `<a class="tag">`. Клик по тегу → фильтр. Клик по тексту → фокус, позиция каретки из `document.caretPositionFromPoint`. Нажатие заменяет static-элемент на editable, поэтому браузерное выделение протяжкой от этого нажатия не стартует (оно привязано к удалённому элементу). Пока кнопка зажата, `Row.followDrag` ведёт выделение сам: от точки нажатия до точки под указателем (`offsetNear`, `selectRange`), не выходя за строку. Иначе выделять получалось только вторым нажатием.
- **editing** (одна строка с фокусом): `<div contenteditable="plaintext-only">` с той же типографикой, поэтому вёрстка не прыгает. Инвариант — внутри ровно один text node, тогда смещение каретки = `Selection.anchorOffset`. На `input` читаем `textContent` и применяем `setText`. Источник истины на время набора — DOM, строку не перерисовываем, иначе прыгнет каретка. При blur строка возвращается в static, и теги подсвечиваются.
- Во время IME-композиции (`isComposing`) горячие клавиши не обрабатываются.

**Шрифт: только системный моноширинный, без веб-шрифтов.** `font-family: ui-monospace, monospace` (переменная `--font-text` в `src/index.css`):
- macOS/Safari: `ui-monospace` → SF Mono;
- Linux: `monospace` идёт через fontconfig (на этой машине это UbuntuMono Nerd Font, кириллица есть);
- Windows: шрифт берётся из настроек браузера (обычно Consolas).

Размер задан явно в px (`--font-size: 17px`). Без этого `monospace` упадёт до браузерных 13px. Отступ уровня — `--indent: 38px` (на узком экране 28px); виртуализатор не предполагает его, а измеряет.

Моноширинный шрифт помогает виртуализатору: ширина строки в символах известна (`ширина колонки / 1ch`), поэтому высоту неизмеренной строки можно точно оценить как `ceil(длина / символов_в_строке) × line-height`. Скролл почти не прыгает.

**Оформление: компоновка Workflowy, палитра Claude.**
- **Компоновка:** тонкая шапка (название, поиск, меню «⋯» с темой и синхронизацией) и одна центральная колонка шириной `--column: 80ch`. Bullet'ы — точки 6 px, свёрнутый bullet — с ореолом. Тонкие направляющие идут от точки каждого предка вниз через его детей: `.row::before`, повторяющийся градиент шириной в `--depth` уровней. Стрелка свернуть/развернуть стоит в 23 px левее центра точки; пока курсор над списком, она видна у всех bullet'ов с детьми, у строки под курсором — ярче.
- **Цвета — из дизайн-системы Claude, с октября 2026 по палитре `Reference/color_pallete.png`:**
  - светлая тема: кремовый холст `#faf9f5`, тёплый тёмный текст, бежевые линии;
  - тёмная тема: нейтральный графит `#262624` (было коричнево-чёрное `#1c1b18`), текст `#f0eee6`, поверхности и линии — шаги того же графита (`#2f2f2c`, `#393936`, `#3a3a37`);
  - коралл — точки пунктов, рамки задач, фокус, каретка, выделение: `#d97757` на графите (4,9:1), на креме на шаг глубже, `#c96442` (3,7:1). Раньше точки были серыми и темнели под курсором; теперь они всегда коралловые и под курсором только растут;
  - жирное голубое, курсив зелёный (`--bold`, `--italic`, см. «Жирный и курсив»); цвета заголовков H1–H5 из той же палитры (`#e06c5e`, `#d97757`, `#d4a53c`, `#8fae63`, `#7ba2d6`) ждут заголовков, которых пока нет;
  - теги — коралловые ссылки (на креме темнее, `#a9583e`, ради контраста);
  - найденное — янтарная подсветка.
  Шрифты Claude лицензионные, поэтому шрифт по-прежнему системный моноширинный (см. выше). Знак Anthropic не используется.
- **Редизайн «зрелее и крупнее»** — по референсам Linear (структура ощущается, а не видна; глубина — шагами светлоты, а не тенями; акцент только для состояний), iA Writer (крупный моноширинный текст и колонка для чтения) и Tana (точка с ореолом = есть содержимое):
  - **Размеры.** Текст 17 px, колонка 72ch (на узком экране текст 16 px). Шапка 64 px, поиск 44 px со скруглением 12 px, кнопка меню 40 px (на телефоне шапка 56 px и поиск 40 px, см. ниже).
  - **Плотность и геометрия строк — по скриншоту Workflowy** (локальная папка `Reference/`, в репозиторий не попадает: на скриншоте личные записи), шрифт прежний:
    - интервал 1,53 (26 px при 17 px), отступ строки 2 px сверху и снизу: шаг однострочного пункта 30 px (`ROW_PAD = 4` в `Outline.tsx`);
    - коробка bullet'а `--bullet: 20px`, точка 6 px, ореол свёрнутого 20 px, зазор до текста 6 px: от центра точки до текста 16 px (`BULLET_GAP = 26`);
    - отступ уровня 38 px, направляющие идут ровно через центр точки предка;
    - заметка — сразу под текстом, без зазора (`NOTE_SCALE = 0.81`);
    - заголовок zoom 28 px, список начинается в 14 px под ним; на главной — в 14 px под полосой крошек (`PAD`);
    - «+» под списком — голый плюс 24 px по центру колонки точек, круг-подложка только при наведении;
    - подложка редактируемой строки выходит на 8 px в стороны и лишь на 2 px вверх и вниз: между строками 4 px, соседей она не задевает.
  - **Отклик.**
    - Редактируемая строка лежит на мягкой подложке `--surface`.
    - Теги и найденное — плашки.
    - Обе подложки нарисованы `box-shadow`-растяжкой и не сдвигают текст: начало редактирования не меняет вёрстку.
    - Точка под курсором увеличивается, у «+» появляется круглая подложка.
    - У кнопок видимые кольца `:focus-visible`.
    - В поиске подсказка-клавиша `Ctrl F` / `⌘ F`.
  - **Один авторский момент движения:** смена темы раскрывается кругом от пункта меню (View Transitions API, `toggleTheme` в `theme.ts`). При `prefers-reduced-motion` переключение мгновенное, все переходы обнуляются.
  - **Значки** — только нарисованные SVG одной толщины линии, никаких символов-заменителей.
  - **Виртуализатор** измеряет `--indent` пробником, а не предполагает его, потому что отступ зависит от ширины экрана.
- **Телефон (ширина ≤ 640 px; целевой — OnePlus 8, 412×915 CSS-пикселей при DPR 2,625).** Шапке не хватало места: логотип, поиск, облако, «⋯» и тема по 40 px не помещались в 412 px, а на 375 px и уже страница становилась шире экрана. Теперь:
  - шапка 56 px, логотип — только коралловый знак, поиск 40 px с короткой подсказкой «Поиск и #теги», без `Ctrl F`;
  - облако синхронизации и переключатель темы переехали в меню «⋯» (сначала только на телефоне, затем по просьбе пользователя и на компьютере, см. ниже);
  - у строки поиска `min-width: 0`: иначе собственная ширина поля ввода вместе со счётчиком выталкивала «⋯» за край экрана;
  - меню не шире экрана минус 24 px, пункты высотой от 44 px (под палец), длинные переносятся; при нехватке высоты меню прокручивается;
  - диалоги с меньшими полями, колонки справки по клавишам сужаются до ширины экрана;
  - ширина задана дважды, в `@media (max-width: 640px)` (`index.css`) и в `view/screen.ts` (сигнал `narrow` через `matchMedia`): CSS меняет размеры, а сигнал — подсказку в поиске.
  Альбомная ориентация (915×412) шире порога и получает обычную шапку, но ниже: при высоте ≤ 480 px шапка 52 px. ## 6. Реактивность (SolidJS)

- `rowsVersion: Signal<number>` — увеличивается при изменении VisibleRows. На него подписан только виртуализатор.
- `nodeSignal(id)` — сигналы по узлам, создаются лениво и только для отрисованных строк. `applyOp` дёргает сигнал изменённого узла. Перерисовывается одна строка, остальное не трогается.
- `focus: Signal<{id, caret}>`, `filter: Signal<FilterState | null>`.
- Сам `Doc` нереактивный, и его можно тестировать без DOM.

## 7. Теги и фильтрация (главная фича)

**Парсинг** (`src/model/tags.ts`): `/(?<=^|[\s(])#([\p{L}\p{N}_]+(?:-[\p{L}\p{N}_]+)*)/gu`. Тег начинается в начале текста или после пробела / «(», состоит из букв и цифр любого алфавита и `_`, внутри может быть дефис (`#война-и-мир`). Регистр приводится к нижнему (`#Пьер` == `#пьер`). `a#b`, `#`, `##` — не теги.

**Два набора тегов: `#` и `@`** (октябрь 2026). `@тег` работает точно так же, как `#тег`: те же правила начала и состава, индекс, клик по тегу, фильтр в поиске (`@иван`, `-@отпуск`, `OR`), подсказка при наборе. Отличается только знаком, и это отдельный набор для смыслового разделения: `#иван` и `@иван` — разные теги. Регулярка — `([#@])(…)`, а `a@mail.ru` тегом не считается, как и `a#b`. Ключи в индексе и в запросе — `tagKey`: `#имя` остаётся просто «имя», как было всегда (старые фильтры и тесты не меняются), `@имя` хранится как «@имя». Обратно в текст ключ превращает `tagText` (клик по тегу кладёт в поиск `#имя` или `@имя`). Подсказка после `@` предлагает только `@`-теги, после `#` — только `#`-теги. e2e: «@ offers @tags only, and a click on one filters by it…»; unit: `tags`, `search`, `complete`.

**Индекс:** `TagIndex = Map<tag, Set<NodeId>>`.
- `setText` → `parseTags(new)` → разница со старым `node.tags` → добавить/убрать id в нужных `Set`. Стоимость — O(длина текста одного bullet'а).
- `create` / `delete` — так же, по всем узлам поддерева.
- При загрузке индекс строится одним проходом: 200 тыс. bullet'ов и 9 млн знаков — 54 мс. Тексты без `#` регулярка не трогает.

**Применение фильтра `#tag`:**
1. `matches = TagIndex.nodesWithPrefix(tag)`, k узлов. Тег в запросе совпадает **по началу**, как слово (пользователь: «поиск по словам: каждый новый символ фильтрует выдачу; теги так не делают: пишу `#` — вижу все теги, `#n` — ничего, `#next` — появляются»): `#n` находит `#next` и `#note`, `#ne` — только `#next`. Проход по ключам индекса (различных тегов немного); если подходит один тег, берётся его `Set` без копии, иначе объединение. `#` и `@` не смешиваются: ключ `@`‑тега начинается с `@`. По началу же работают исключение `-#тег` и подсветка активных тегов (`.tag.active`). Одинокий `#` по‑прежнему слово: находит все пункты с `#`.
2. **keep-set** = matches ∪ все их предки. Поднимаемся по `parent` и останавливаемся, как только встретили узел, который уже в наборе. Итого O(размер keep-set), а не O(k·глубина).
3. VisibleRows строится обходом от root (`Filter = { keep, open }` в `src/model/rows.ts`). Узел из keep показывает только детей из keep — путь к совпадениям. Совпавшие узлы поэтому **свёрнуты** (как в Workflowy), а у узла пути с другими детьми есть кружок «есть скрытое». Клик по bullet'у или Ctrl+↓ добавляет узел в `open`, и тогда видны все его дети, а ниже работает обычное `collapsed`. Раскрытие в фильтре временное: оно не меняет `node.collapsed`, не попадает в историю и на диск.
4. Виртуализатор рисует первый экран.

Размер всего документа на стоимость **не влияет**, важно только, сколько найдено. Замер (Chromium, 200 тыс. bullet'ов, 9 млн знаков, тег на ~3300 bullet'ах, ~4900 строк с путями): keep-set 2–3 мс, строки 4–10 мс, от клика до отрисованного кадра 22 мс. Сброс фильтра пересобирает все 200 тыс. строк — 20 мс.

**Правка в режиме фильтра.** Изменение текста строки не меняет: если стереть тег у bullet'а, он не исчезает из-под каретки. Вставленные и перемещённые bullet'ы остаются видимыми (`VisibleRows.admit`): если родитель показывает только путь, узел добавляется в keep и open, а его скрытые предки — в keep. Например, Tab под скрытого соседа проявляет этого соседа. Повторный клик по тегу пересчитывает выборку с нуля. Рандомизированный тест проверяет, что после любой команды под фильтром строки совпадают с полной пересборкой и что bullet, куда команда ставит каретку, виден.

**Интерфейс.** Клик по тегу в любой строке включает фильтр (редактирование при этом выходит). Сверху панель: тег, число bullet'ов, «× сбросить (Esc)». Esc сбрасывает фильтр: если строка редактировалась, редактирование продолжается уже в полном документе и прокручивается к ней. Следующий Esc выходит из редактирования. Новый фильтр показывает результат с начала.

**Несколько тегов** в запросе (`#a #b`) — пересечение `Set`, начиная с самого маленького. `OR` — объединение по альтернативам, `-#тег` — разность; индекс тот же.

## 7а. Поиск по тексту

Поиск и фильтр по тегу — один механизм: строка поиска вверху, клик по тегу подставляет в неё `#тег`, а результат показывается тем же фильтром (совпадения с путём, правка прямо в результатах, §7).

**Запрос** (`src/model/search.ts`, `parseQuery`):
- слова через пробел должны **все** встретиться в одном bullet'е;
- `"фраза в кавычках"` ищется целиком, `#тег` берётся из TagIndex;
- `-слово`, `-"фраза"`, `-#тег` исключают;
- `is:done` и `-is:done` оставляют только выполненные или только невыполненные;
- `OR` (или `ИЛИ`, `|`) разделяет альтернативы (`Clause`): пункт подходит, если подходит любая из них;
- запрос из одних исключений означает «всё, кроме».

Подсвечиваются только искомые слова, не исключённые. Сравнение без учёта регистра, «ё» = «е» (`normalize` сохраняет длину текста, поэтому найденные смещения годятся для подсветки). Регулярных выражений в запросе пока нет.

**Индекс** (`TextIndex`): нормализованная копия текста каждого bullet'а, обновляется по ops так же, как TagIndex. Поиск — один проход `includes` по готовым строкам, без перевода в нижний регистр на каждый запрос. Если в запросе есть тег, перебираются только bullet'ы с этим тегом. Копия строится лениво: кусками по ~1000 bullet'ов, пока браузер простаивает (`requestIdleCallback` с проверкой `timeRemaining`). Если поиск пришёл раньше, он достраивает остаток сам. Так её построение (131 мс на 200 тыс. bullet'ов) не добавляется к загрузке и не блокирует ввод одним куском. Память: ещё одна копия текстов, ~18 МБ на 9 млн знаков кириллицы.

**Интерфейс:** Ctrl/Cmd+F переводит курсор в строку поиска (встроенный поиск браузера не видит виртуализированные строки). Поиск идёт по мере набора, не чаще раза за кадр. Совпадения подсвечиваются (`decorate`), справа число найденных bullet'ов. Enter или ↓ — редактировать первое совпадение. Esc в строке поиска сбрасывает поиск, Esc в редактируемой строке тоже сбрасывает поиск, а редактирование продолжается в полном документе.

**Замеры** (Chromium 152, 200 тыс. bullet'ов, 9 млн знаков; поиск — вычисление совпадений, строки — keep-set и пересборка списка):

| Запрос | Совпадений | Поиск | Строки |
|---|---|---|---|
| `наташа смотрел` | 6 560 | 23 мс | 13 мс |
| `бородино` | 27 992 | 19 мс | 25 мс |
| `"тихо быстро"` | 705 | 19 мс | 5 мс |
| `#война кутузов` | 474 | 3 мс | 2 мс |
| `а` (почти всё) | 181 585 | 20 мс | 69 мс |

От нажатия до отрисованного результата (e2e, через секунду после загрузки) — 48–58 мс, включая ожидание кадра. Если искать в первую же секунду после загрузки, первый поиск может дополнительно достраивать индекс, до +130 мс. Если когда-нибудь полный проход станет узким местом, следующие шаги — триграммный индекс или перенос поиска в Web Worker.

**Избранные поиски** (`SearchBar.tsx`, октябрь 2026; пользователь: «в поиске можно сохранить то, что набрал — иконка звёздочки, контур, а когда выбрал — залита цветом в рамках цветовой гаммы; при фокусе на поиске первым в списке появляется сохранённое; ограничь список, добавь скролл, высоту продумай для разных устройств, включая OnePlus»).
- Пока в поле что-то набрано, справа стоит звёздочка: контур — не сохранено, залита кораллом (`--primary`) — сохранено (`aria-pressed`); повторное нажатие убирает из избранного. Нажатие не отнимает фокус у поля.
- При фокусе под полем выпадает список «Избранное», последний сохранённый первым; пока набирается текст, список сужается до сохранённых, которые его содержат (без самого набранного). Нажатие запускает поиск, × убирает запрос; нажатия не отнимают фокус, поэтому клавиатура на телефоне не прячется.
- Не больше `SAVED_MAX` = 20: сохранение 21‑го убирает самый старый с подсказкой. Хранится в браузере (`localStorage['listik-saved-searches']`, `Outliner.savedSearches` / `toggleSaved`), как тема; между устройствами не синхронизируется.
- Высота: до 8,5 строки на компьютере (36 px), до 8,5 строки по 44 px на сенсорном экране, но не больше 40 % видимой высоты (`40dvh`): на OnePlus 8 с поднятой клавиатурой (412×540) это ≈216 px, около пяти строк. Пока ниже есть ещё пункты, нижний край гаснет (`.saved-searches.more`). e2e: «saved searches».

## 7б. Zoom в bullet

Как в Workflowy: клик по точке bullet'а или Alt+→ делает его заголовком страницы, а его детей — верхним уровнем. Над заголовком «хлебные крошки» (`Главная › …`), Alt+← или крошка выходит на уровень вверх, и курсор встаёт на bullet, из которого вышли. Свернуть/развернуть теперь — стрелка слева от bullet'а (видна при наведении) и Ctrl+↑/↓.

- **Модель:** `VisibleRows.top` — чьи дети показаны на глубине 0 (корень или bullet, в который вошли). `setTop` пересобирает строки. Операции вне поддерева `top` строк не трогают (`contains`). Сам `top` показывает детей независимо от своего `collapsed`.
- **Команды не выводят строку за пределы zoom:** Shift+Tab и перемещения на верхнем уровне останавливаются на `rows.top`. Enter в заголовке создаёт первого ребёнка (`prependChild`).
- **Поиск и теги внутри zoom** ищут только в его поддереве. `keepSet` строится от `top`, поэтому пустой результат — пустой экран.
- **Переход сбрасывает поиск, крошки — нет.** Смена zoom точкой, Alt+→/←, ссылкой, «назад» очищает активный поиск: пользователь нашёл пункт и вошёл в него, чтобы увидеть его целиком, а не одни совпадения (раньше поиск перезапускался внутри нового места). Сначала `setTop` (под фильтром это дешёвая пересборка одних путей), потом сброс фильтра пересобирает только новое место. Поиск, начатый уже внутри zoom, ищет в его поддереве, как раньше.
- **Крошки поиск сохраняют** (пользователь: «Если переходим по крошкам — поиск не должен сбрасываться, позволяя видеть результат поиска на разных уровнях»). Крошка и «Главная» из zoom вызывают `zoomTo(id, keepSearch)`: после `setTop` тот же запрос применяется заново (`setQuery(query, true)` → `applyQuery` по новому `top`), поэтому найденное видно уже в более широком месте. «Главная» на самой главной по-прежнему сбрасывает поиск и сворачивает верхний уровень (`goHome`).
- **Найден сам заголовок.** Поиск в zoom ищет внутри пункта и в нём самом. Если запросу отвечает сам пункт, в который вошли (так бывает, когда по крошкам поднялись к искомому пункту: пользователь — «если в поиске вбить что-то и это будет крайней точкой в крошках — мы увидим ноду в виде заголовка, а ниже неё ничего не будет»), `applyQuery` ставит фильтр `{keep: {zoom}, open: {zoom}}`: под заголовком всё как без поиска, со своей свёрткой и подсветкой совпадений, а счётчик считает и сам пункт. e2e: «gone up by the path to the very bullet searched for: everything inside it shows». e2e: «going into a bullet found by a search clears the search», «going up by the path keeps the search», «"Главная" goes home with the search…».
- **Адрес:** zoom хранится в адресе как `#/<id>` (`src/view/zoom-hash.ts`). «Назад» и «вперёд» браузера выходят и входят, перезагрузка сохраняет место. Адрес, не указывающий на существующий bullet, отбрасывается без новой записи в истории.
- **Крошка «Главная» на главной странице** (раньше это делал логотип, теперь он ведёт в сегодня, §7о) — обзор: выход из zoom, сброс поиска, прокрутка к началу и сворачивание всех пунктов верхнего уровня, у которых есть дети (`collapseChildren`, глубже ничего не трогается). Сворачивание — часть документа и один шаг отмены. На 200 тыс. bullet'ов (~700 глав) — 17–24 мс до кадра.
- **Своя крошка — обзор, ещё раз — обратно; линии сворачивают** (пользователь: «Ситуация — открываешь и получаешь огромное дерево. Нужно быстро всё свернуть, найти нужный узел и уже потом открывать их»; выбраны клик по линиям и своя крошка). Последняя крошка (где вы сейчас) и «Главная» на главной — `Outliner.toggleLevel`: сворачивает все пункты первого уровня в этом месте, у которых есть дети; если сворачивать нечего — разворачивает то, что свернула в прошлый раз (`levelFolded`), а если с тех пор там что-то менялось — все. Каждое — один шаг undo. Вертикальные направляющие (`.row::before`, по линии на уровень предка) кликабельны: `guideAt` в `Outline.tsx` по координате указателя в отступе строки находит столбец (допуск ±5 px, на сенсорном ±10), поднимается по `parentKey` до предка этого уровня и сворачивает его (`Outliner.fold`, строка предка остаётся в виду); под указателем линия загорается кораллом на всю высоту ветки предка (`.guide-hot`), курсор — указатель. e2e: «a click on a guide line folds…», «the place's own crumb folds the first level inside…».
- **Конец списка — до середины экрана.** Под последней строкой (и «+») оставлено пустое место в половину высоты списка (`tail()` в `Outline.tsx`), чтобы последние пункты можно было поднять к середине экрана и работать там, а не у нижнего края. Это работает на десктопе и на телефоне. Заодно у браузера появляется куда прокрутить при наборе в последней строке. e2e: «the end of a long list scrolls up to mid-screen».
- **Кнопка «+»** под списком — и в zoom (как в Workflowy), и на главной — добавляет пустой bullet последним ребёнком (`appendChild`) и ставит в него курсор: список можно наполнять без клавиатуры. Один клик — один шаг отмены. Во время поиска кнопка скрыта. Список виртуализирован, поэтому кнопка позиционируется не в потоке строк, а по их суммарной высоте (`total`), и высота области прокрутки учитывает её строку.
- **Крошки и заголовок** (`ZoomHeader.tsx`). Полоса крошек (`Crumbs`) стоит над списком и не прокручивается. В ней путь от корня до текущего места включительно: «Главная › … › узел», где сам узел — последняя крошка, не ссылка (`aria-current`). На главной там одна «Главная». Путь занимает одну строку и крошки не сокращает (пользователь: «строка с крошками скролится, а не сокращается; всегда видим полностью ближайшие ноды к текущей, чтобы быстрее можно было вернуться назад; особенно важно для мобильной версии»): крошки не сжимаются (`flex: none`, без многоточия), длинный путь прокручивается вбок (и пальцем) и держится в конце — при смене пути, переименовании крошки и изменении ширины полосы (`ResizeObserver`). Если слева путь ушёл за край, этот край гаснет (`.crumbs.clipped`, `mask-image`). Многоточием сокращается только последняя крошка — текущий пункт — длиннее половины полосы: её полный текст стоит в заголовке под ней, а место нужнее родителям. e2e: «a path wider than the screen scrolls instead of shortening crumbs». Пока список прокручен, под полосой появляется тонкая линия.
  Заголовок узла (`ZoomTitle`) прокручивается вместе со строками, как в Workflowy. Он лежит в начале области прокрутки (`.spacer`) абсолютным блоком, `Outline.tsx` меряет его высоту (`ResizeObserver`) и сдвигает на неё всё, что считается от верха списка: окно строк, диапазон виртуализации, докрутку к строке и якорь при изменении высоты строк выше экрана, «+», высоту области (`top()` = `PAD` + высота заголовка). Так виртуализатор по-прежнему считает от верха `.spacer`, а заголовок в его расчёты не входит. e2e: «the title scrolls away with the list; the path stays, ending at the bullet».
  Вне правки заголовок показан как строка: теги, ссылки, жирный и курсив, совпадения поиска (`Pieces` из `Row.tsx`, маркеры скрыты, но лежат в DOM, поэтому смещения совпадают с текстом). Клик по тегу фильтрует (поиск в пределах zoom), по ссылке — ведёт к пункту, по остальному тексту — открывает редактор (`TitleEditable`) с кареткой там, где клик; уход из редактора снова показывает оформленный заголовок. Запрос `titleRequests` (Alt+→ в пункт без детей) тоже открывает редактор. e2e: «the title shows tags like a row».
- **Заголовок** редактируется как строка: набор идёт через `o.type`, работают undo и Esc. ↓ переходит к первому ребёнку.
- **Удаление:** если удалить bullet, внутри которого вы находитесь (или отменить его создание), zoom выходит на главную.
- **Сигналы узлов** теперь со счётчиком ссылок (`acquire` / `release`): один bullet могут одновременно показывать заголовок, крошки и строка.

Рандомизированный тест правит документ внутри zoom: строки совпадают с полной пересборкой, всё видимое лежит внутри, bullet'ы снаружи не сдвигаются.

## 7в. Экспорт, импорт, резервные копии

Документ живёт в IndexedDB одного браузера, поэтому выгрузка в файл — главная страховка.

- **Форматы** (`src/model/outline-text.ts`):
  - Markdown: `- текст`, 2 пробела на уровень;
  - OPML 2.0: формат обмена Workflowy и других outliner'ов, со спецсимволами XML.

  Оба формата читаются обратно.
- **Разбор текста с отступами** (`parseIndented`):
  - вложенность определяется только относительным отступом, пробелами или табами (таб = 4);
  - маркеры `-` `*` `+` `•` `1.` и знаки заголовков `# ` отбрасываются, `#тег` остаётся;
  - пустые строки пропускаются.

  Так читаются и Markdown, и текстовый экспорт Workflowy, и просто текст с отступами.
- **Импорт** (меню «⋯» → «Импорт из файла…») добавляет пункты последними детьми текущего уровня: корня или bullet'а, в котором вы находитесь (`appendTrees`). Каждое дерево вставляется одной операцией `insert` с поддеревом, и весь импорт — один шаг отмены.
- **Вставка нескольких строк** строит дерево (`insertTrees`): текст первой строки встаёт на место курсора, её дети становятся первыми детьми текущего bullet'а, остальные деревья идут ниже, а хвост текста после курсора переходит в конец последнего.
- **Автокопия в папку** (`src/persist/backup.ts`, Chrome и Edge, File System Access API):
  - вы выбираете папку, дескриптор хранится в `meta`/`backupDir`;
  - при изменениях документ пишется в `listik-ГГГГ-ММ-ДД.md` не чаще раза в 5 минут и при уходе со вкладки;
  - один файл на день, так что в папке копится история по дням.
  
  После перезагрузки браузер обычно снова спрашивает разрешение: тогда в меню «Автокопия на паузе — продолжить», нужен клик. Ошибки записи показываются там же («повторить»).

## 7д. Задачи (чекбоксы) и заметки

- **Модель.** У узла есть `todo` (задача, рисуется чекбоксом) и `done` (выполнена). Выполненной может быть только задача, обычный пункт — просто текст. Операции: `setTodo`, `setDone`, `setNote` (последняя с `at`, как `setText`). Формат снимка v3 добавляет `todo`. Снимки v1/v2 читаются, а в v2 всё выполненное и было задачей, поэтому выполненное становится выполненной задачей.
- **Ctrl/Cmd+Enter** (`cycleTask`): обычный пункт становится задачей — пустым чекбоксом; у задачи отметка ставится или снимается. На нескольких пунктах сначала все обычные становятся задачами, потом отмечаются все разом.
- **Ctrl/Cmd+Shift+Enter** (`untask`) — задача снова становится обычным пунктом.
- **Клик по чекбоксу** без сдвига мыши ставит или снимает отметку, редактирование строки при этом продолжается. Клик по точке обычного пункта по-прежнему ведёт внутрь (zoom), перетаскивание работает за оба вида.
- **Отсечка по задачам.** В поиске `is:done`, `is:todo` (открытые) и `is:task` (все задачи), с отрицанием через `-`.
- **Заметка:**
  - Shift+Enter переходит из текста в заметку и обратно, Esc из заметки тоже возвращает в текст;
  - ↓ с последней строки текста ведёт в заметку, ↑ с первой строки заметки — в текст;
  - Enter в заметке — новая строка;
  - набор в заметке группируется в шаги отмены так же, как в тексте;
  - строка вне правки показывает первые 3 строки заметки (`.note.clamped`, `line-clamp`, остальное за многоточием); строка в правке — каретка в тексте или в заметке — всю заметку. Оценка высоты в виртуализаторе берёт не больше `NOTE_LINES` = 3 строк заметки;
  - у пункта, в который вошли (zoom), заметка показана целиком под заголовком (`ZoomTitle`, `.zoom-note`): теги и ссылки в ней кликабельны, клик по тексту — правка (`TitleNoteEditable`). Shift+Enter в заголовке ведёт в заметку (создаёт её, если её нет), Shift+Enter, Esc, ↑ с первой строки или Backspace в пустой заметке — обратно в заголовок, ↓ с последней строки — в первую строку списка; ↓ с последней строки заголовка ведёт сначала в заметку. e2e: «a note shows its first 3 lines until its bullet is edited…», «a bullet without a note gets one from the zoom title».
- **Перевод строки в заметке.** Chromium вставляет `\n\n`: второй перевод — заглушка, чтобы пустая последняя строка была видна. Поэтому DOM заметки не переписывается: модель хранит текст без одной завершающей `\n`, а при записи извне заглушка добавляется обратно.
- **Выполненные всегда видны** (пользователь, октябрь 2026: «Убрать функцию скрытия уже сделанного. Выполненное просто вычеркивается и всегда отображается»). Прежнее скрытие (Ctrl+O, пункт меню, `VisibleRows.setHideDone`, `rows.unfolded` без учёта скрытых) убрано целиком: отметка «сделано» строк не меняет (`setDone` в `VisibleRows.op` пропускается, как правка текста), строка остаётся на месте зачёркнутой и бледной (`.row.done .text`). Старая настройка `listik-hide-done` стирается при запуске. Ctrl+O больше не перехватывается.
- **Теги и поиск читают текст вместе с заметкой** (`content` в `tags.ts`). Backspace не склеивает пункт с заметкой, чтобы её не потерять.
- **В файлах:**
  - Markdown: задачи — `- [ ] пункт` и `- [x] пункт`; строки заметки — без маркера, с отступом на уровне текста;
  - OPML: атрибуты Workflowy `_complete` и `_note`, наш `_task="true"` для задачи; переводы строк кодируются как `&#10;`.

## 7е. Выделение нескольких пунктов

- **Как выделить:**
  - Shift+↑/↓ на крайней строке текста — этот пункт и соседний;
  - Shift+клик — диапазон от редактируемого (или уже выделенного) пункта.
- **Что выделено** (`Outliner.selection = { anchor, head }`): видимые строки между anchor и head, расширенные до целых поддеревьев. Набор и «корни» (выделенные, чей родитель не выделен) кэшируются по версии строк.
- **Клавиши** (`onSelectionKeys`), каждая команда — один шаг отмены:
  - Shift+↑/↓ — двигать head;
  - Tab / Shift+Tab — вложить / вынести блок (`indentMany`; если первый пункт вложить некуда, блок не двигается — иначе он развалился бы);
  - Alt/Ctrl+Shift+↑/↓ — переместить блок целиком (не дальше краёв и zoom);
  - Ctrl+L — по кругу (`cycleTask`): обычные — в задачи, затем открытые — отмечены, затем все — снова обычные (до октября 2026 было Ctrl+Enter, теперь Ctrl+Enter ничего не делает);
  - Backspace / Delete — удалить;
  - Ctrl+C / Ctrl+X — скопировать / вырезать как Markdown (`markdownOf`);
  - Ctrl+A — всё видимое.

  Esc, Enter, стрелка без Shift или клик снимают выделение.

## 7ж. Перетаскивание

Тянуть можно за точку bullet'а (`src/view/drag.ts`). Если мышь сдвинулась меньше чем на 4 px, это клик, и он ведёт внутрь пункта (zoom). Иначе начинается перетаскивание:
- тянется сам пункт с поддеревом или, если он в выделении, всё выделенное;
- перетаскиваемые строки приглушены;
- коралловая линия показывает место и уровень. Уровень следует за x указателя в допустимых пределах: не мельче следующей строки и не глубже ребёнка предыдущей.

Бросить пункт между строками перетаскиваемого блока или внутрь его поддерева нельзя. Esc отменяет перетаскивание, у края списка он сам прокручивается.

**Пальцем** перетаскивание начинается иначе: точку нужно подержать 350 мс (`LONG_PRESS`), телефон коротко вибрирует. Короткое касание — как клик: zoom или отметка задачи. Если палец сдвинулся больше чем на 8 px раньше, это прокрутка или смахивание, а не нажатие. Чтобы список прокручивался и тогда, когда палец лёг на точку, у неё `touch-action: pan-y` (раньше было `none`, и любое движение по точке тащило пункт). Браузер, начав прокрутку, сам отменяет указатель (`pointercancel`). После удержания прокрутку останавливает собственный непассивный `touchmove` у точки (`Row.tsx`): он отменяет событие, пока идёт перетаскивание. Делегированный обработчик Solid на `document` для этого не годится: Chrome считает такие обработчики пассивными. Контекстное меню и выделение текста на удержании отключены. e2e: «a tap on a bullet zooms in; a held bullet drags; a swipe from it does neither» (касания через CDP `Input.dispatchTouchEvent`). Со старым кодом смахивание переносило пункт.

Модель — `moveManyTo(ids, parent, after)`, один шаг отмены. Новые ключи порядка лежат строго между двумя соседними ключами, которые существуют сейчас, поэтому не могут совпасть с ключом перемещаемого пункта, который ещё не переехал. Если бросить «после самого себя», точкой отсчёта становится ближайший неперемещаемый предшественник.

## 7з. Справка по клавишам

`?` (когда ничего не редактируется), Ctrl/Cmd+/ в любом месте или пункт меню открывают панель с клавишами, сгруппированными по задачам: правка, структура, переходы, поиск, выделение (`src/view/Shortcuts.tsx`). Это нативный `<dialog>`: Esc и клик мимо закрывают его, фокус возвращается на место. На Mac показываются ⌘ и ⌥.

## 7г. Приложение без сервера (PWA)

`npm run app` собирает Listik и запускает его на `http://127.0.0.1:4173`. Один раз открыть этот адрес и установить: в Chrome — значок «Установить» в адресной строке. Дальше Listik открывается отдельным окном, без запущенного сервера и без интернета.

- **Манифест** `public/manifest.webmanifest`: имя, `display: standalone`, значки 192/512, maskable и SVG. Значки рисуются из `public/icons/icon.svg` (`magick`).
- **Service worker** `public/sw.js`, регистрируется только в сборке, чтобы в разработке кэш не подменял dev-сервер:
  - страница идёт сначала из сети, поэтому новая сборка приходит при следующем открытии, а без сети берётся из кэша;
  - файлы сборки с хэшем в имени берутся сначала из кэша, потому что их содержимое никогда не меняется.
- **Данные привязаны к адресу.** У dev-сервера (`:5173`) и приложения (`:4173`) разные IndexedDB. Перенести документ между ними можно экспортом и импортом (§7в).
- **e2e:** Playwright-проект `pwa` поднимает `vite build` + `vite preview`, проверяет манифест и контроль service worker'а, затем отключает сеть и перезагружает страницу: приложение открывается вместе с данными.

## 7и. Корзина, общие ключи порядка, часы

Три изменения модели ради синхронизации; все они нужны и без неё.

- **Корзина.** У `Doc` два корня: `root` и скрытый `TRASH`. Удаление пункта (Backspace, Ctrl+Shift+Backspace, удаление выделения, отмена создания — `invert(insert)`) — это `move` в корзину, а не `remove`. Ключ порядка в корзине — время удаления в base‑36 (`trashKey`), поэтому корзина отсортирована по возрасту. Так правка с другого устройства, пришедшая к уже удалённому пункту, применяется в корзине и не теряется, а отмена удаления работает между устройствами. Компакция (`purgeTrash`) уничтожает записи старше 30 дней; чистка локальна и не синхронизируется: операция о вычищенном пункте просто отбрасывается. `VisibleRows` корзину не видит (она не под `root`), `TagIndex` и `TextIndex` исключают её: при `move` через границу корзины поддерево входит в индексы или покидает их. Снимок v4 хранит строки корзины после строк документа (`parent = -2`).
- **Панель «Корзина»** (пользователь, октябрь 2026: «В меню должен появиться пункт с корзиной. Через него я могу увидеть недавно удалённые блоки и иметь возможность отменить удаление (вернуть их на прежнее место)… не новое окно, а панель внутри основного. Чтобы не перебивать фокус и при этом я могу продолжить работу с основным деревом»).
  - **Откуда удалено.** Удаление (`remove` в `commands.ts`) пишет в ключ порядка в корзине не только время, но и прежнее место: `deletedKey` = `время|order|parent` (`model/trash.ts`). Время остаётся впереди фиксированной ширины, поэтому сортировка, `trashTime` и `purgeTrash` прежние; место — часть операции `move`, а значит, уходит в синхронизацию и переживает компакцию без новой колонки в снимке. В ключах порядка и id нет `|`. В корзину попадают и иначе (отмена создания `invert(insert)`, чужое удаление через слияние) — у них голый ключ времени, и `deletedFrom` даёт null.
  - **Список** (`deletedEntries`): каждый удалённый блок один раз, новые сверху; без пустых строк (нет текста, заметки и детей — Backspace на пустой строке) и без попавшего в корзину не удалением.
  - **Стёртый, затем удалённый** (пользователь: «Если удалил название и потом удалил ноду (удалял бэкспейсом с конца строки) — это тоже должно попасть в корзину и попасть целиком»). `Outliner.type` запоминает, какой текст был у пункта, когда его начали стирать (`erased`; набор новых букв забывает). Если команда (`Outliner.run`) удалила такой пункт пустым, в той же транзакции `keepErased` возвращает ему этот текст уже в корзине: запись видна и возвращается с названием. Undo удаления возвращает пустой пункт, каким он был; память только на сессию. Вложенное в блок считается один раз на запись (кэш в `Trash.tsx`: содержимое корзины почти не меняется, а блок бывает большим).
  - **«Вернуть»** (`restoreDeleted`, `Outliner.restoreDeleted`): одна операция `move` из корзины на прежнее место, между теми же соседями (прежний ключ порядка; равные ключи допустимы). Если места нет (родитель тоже удалён или вычищен) — в конец верхнего уровня с сообщением. Один шаг undo. Курсор встаёт в конец текста возвращённого пункта, на его месте среди соседей (решение пользователя); если этого места нет на экране (другой zoom, свёрнутый предок), сначала zoom в родителя. Копия зеркала, передавшая данные при удалении (`handOver`), сама становится зеркалом наследника, поэтому возвращается копией.
  - **Панель** (`Trash.tsx`) — колонка 340 px справа от дерева (290 px до 960 px ширины), на телефоне — лист под деревом высотой до 42 % экрана; при поднятой экранной клавиатуре прячется (`keyboard`). Дерево (`.main`) и панель — в `.workspace`. Открыта ли — `localStorage` `listik-trash-open`, панель остаётся открытой, пока её не закроют. Кнопки не забирают фокус у строки (`mousedown` без действия по умолчанию), фокус берёт только поле «Найти в удалённом» (Esc очищает его, второй Esc уходит из поля). Записи сгруппированы по дням («Сегодня», «Вчера», «18 октября»), в строке — текст (или первая строка заметки курсивом), время, «+N вложенных», последние два шага пути (весь путь — в подсказке). Показывается до 100 записей, остальное — через поиск. Список реактивен (`Outliner.deleted()` через `rowsVersion`): удалённое появляется сразу. Пункт меню «Корзина» показывает число записей, у открытой — «Скрыть корзину». Во вкладке только для чтения список виден, «Вернуть» недоступна.
  - Тесты: unit `tests/trash.test.ts` (ключ с местом, список без пустых и отменённых созданий, возврат на место и undo, место ушло — в конец, снимок хранит место, копия возвращается копией); e2e «trash» (панель рядом с деревом, удалённое появляется сразу, правка идёт при открытой панели, «Вернуть» — на место с курсором, undo, открыта после перезагрузки; место не на экране — переход туда; место удалено — в конец с сообщением) и «the trash is a sheet under the outline…» (телефон).
- **Общие ключи порядка.** Два устройства, вставившие пункты в одну щель, дают одинаковый дробный ключ. Дети отсортированы по паре (`order`, `id`), равные ключи допустимы, а `Doc.ordersAt` при равных соседях ставит новые ключи после всей серии равных (между равными ключами ничего нет).
- **Часы.** `clock.ts` — гибридные логические часы: монотонные миллисекунды, которые не повторяются на устройстве и перепрыгивают вперёд любую метку, увиденную с другого устройства. `at` у `setText`/`setNote` и `created` берутся из них; по ним решается, чья правка позже.

## 7к. Синхронизация между устройствами

Один пользователь, много устройств, работа без сети. Сервер (`server/index.js`) — упорядоченный журнал **зашифрованных** пачек операций на документ плюс последний зашифрованный снимок и слот ключа; он не понимает содержимого. Слияние целиком на клиенте.

**Протокол** (`src/sync/client.ts`, `engine.ts`):
- Устройство применяет серверный журнал по порядку и запоминает `head` — последний применённый номер. Локальные операции копятся в **outbox** (в `meta`, переживает перезагрузку) и уходят одной пачкой через ~1 с после правки. `setCollapsed` не отправляется: свёрнутость — состояние просмотра устройства.
- **Compare‑and‑append.** Пачка отправляется с `parent = head`; если кто‑то успел раньше, сервер отвечает 409, устройство подтягивает новое, перебазирует и повторяет.
- **Перебазирование.** В одной транзакции: откатить outbox (через `invert`), применить чужие операции, заново наложить outbox — всё через `applyMerged` (ниже). Отправляется outbox как был написан: все устройства прогоняют одну и ту же детерминированную функцию слияния над одним порядком, поэтому сходятся.
- **Цепочка хэшей.** Внутри шифротекста пачки лежит `prev` — SHA‑256 предыдущей пачки. Пачка, которая не расшифровывается или не продолжает цепочку, останавливает синхронизацию с ошибкой: сервер подменил, переставил или потерял записи. AAD шифрования включает код документа и номер пачки, поэтому пачку нельзя переставить на другое место.
- **Снимки.** Раз в 500 пачек (и при создании документа — снимок с номером 0) устройство с пустым outbox выгружает зашифрованный `gzip(serialize(doc))` с номером `head` и хэшем цепочки. Новое устройство (`bootstrap`) начинает со снимка и читает журнал после него. Сервер удаляет пачки, вошедшие в снимок, через `LISTIK_RETENTION` дней; устройство, отставшее дальше, получает 410 и загружает документ заново со снимка, сохранив outbox.
- **Живые обновления.** Поток `GET /events` (fetch со streaming, не EventSource, чтобы передать заголовок авторизации) сообщает новый `head`; плюс подтягивание при возвращении вкладки и при появлении сети.

**Доступ.** Создание документа — первый `PUT keyslot` с токеном; `LISTIK_ALLOW_CREATE=0` закрывает его, не трогая существующие документы и подключение к ним. Неудачные авторизации и обращения к несуществующим документам ограничены: 20 за 10 минут с адреса, дальше 429. Код документа (20 случайных знаков) и токен (32 байта из Argon2id) перебором не берутся; ограничение защищает от шума и диска.

**Слияние** (`src/model/merge.ts`, `merge-text.ts`). `Doc.apply` строг: операция с устаревшим `from` отклоняется. Поэтому чужая операция (и undo, если пункт с тех пор менялся) проходит через `applyMerged`, который превращает её в операции, выполнимые на текущем документе:
- поля независимы: перемещение и правка одного пункта оба применяются;
- текст и заметка сливаются трёхсторонне (`merge3` по `from`/`to` операции и текущему тексту, разность через `fast-diff`); если правки задевают одни и те же слова, побеждает более поздняя по часам, а проигравшая версия дописывается в заметку с пометкой `⚠ Другая версия`;
- `insert` существующего пункта — перемещение; `insert` под отсутствующего родителя — в корзину; `remove` с другого устройства — в корзину;
- `move`, создающий цикл, пропускается; `move` пункта, который уже не там, где ожидалось, всё равно выполняется (его устройство двигало нарочно);
- `setTodo`/`setDone` применяются, если значение отличается; `setCollapsed` чужой — никогда не приходит.

Тесты (`tests/sync.test.ts`) гоняют настоящий сервер в процессе: три устройства случайно правят, отменяют и синхронизируются вразнобой, в конце сходятся побайтно (без учёта свёрнутости); отдельно — конфликт одного текста, снимок и retention, подделанная пачка.

## 7л. Шифрование

Сквозное: сервер и локальная IndexedDB хранят только шифротекст (`src/sync/crypto.ts`, `src/persist/codec.ts`).

- **Ключи.** Пароль + код документа (случайный, он же соль) → Argon2id (64 МиБ, 3 прохода, `hash-wasm`) → **KEK**. KEK заворачивает случайный **ключ документа (DEK)** в слот ключа, который лежит на сервере и локально; смена пароля — перезаворачивание без перешифровки. Из KEK же выводится (HKDF) **токен** для сервера: сервер знает только его SHA‑256 и может отказать или испортить, но не прочитать. Из DEK выводится ключ данных AES‑256‑GCM.
- **Записи.** Кодек хранилища пишет снимок и пачки журнала как `{enc: 1, iv, ct}`; шифрованный кодек читает и старые открытые записи, поэтому включение шифрования — одна принудительная компакция (Worker получает `CryptoKey` через structured clone). Открытый кодек на шифрованной записи бросает `LockedError`.
- **Смена кодека (`Persistence.recode`).** Новые записи сразу идут новым кодеком, а принудительная компакция читает через `recoding(new, old)`: каждую запись сначала новым кодеком, при отказе — старым. Так переход «ключ → другой ключ» и «ключ → открыто» складывает в новый снимок и старые записи, и написанные после переключения. Ошибка этой компакции, в отличие от плановой, пробрасывается: пока она не прошла, хранилище смешанное. До исправления (октябрь 2026) компакция читала только новым ключом; если синхронизацию включали второй раз (первая попытка «Создать» упала после шифрования), снимок и часть журнала оставались под прежним ключом, и после перезагрузки загрузка падала с `OperationError`. `disconnectSync` теперь сначала расшифровывает хранилище и только потом забывает ключ.
- **Восстановление (`Restore.tsx`, `restoreFromServer`).** Если устройство помнит ключ, но локальная копия им не открывается (AES-GCM бросает `OperationError`), вместо ошибки показывается экран «Загрузить с сервера»: `bootstrap` заменяет снимок и журнал снимком сервера, очередь неотправленных пачек (outbox в `syncState`) сохраняется.
- **Устройство.** «Запомнить на этом устройстве» — неизвлекаемый `CryptoKey` в IndexedDB запечатывает DEK и токен; иначе пароль спрашивается при каждой загрузке (`Unlock.tsx`). Это защищает данные на диске, но не от кода, выполняющегося в странице.
- **Доверие к коду.** Приложение раздаётся с GitHub Pages, данные лежат на своём сервере: взлом одного места не даёт одновременно подменить код и прочитать данные. Если раздавать и то и другое с одного сервера, подмена кода остаётся вне модели угроз.

Пока синхронизация не включена, документ хранится открыто, как раньше: пароля нет.

## 7м. Ссылки между пунктами `[[…]]`

Как вики-ссылки в Obsidian и Logseq (октябрь 2026, `model/links.ts`). Пользователь сформулировал так: «`[[` сразу создаёт пару и при вводе ищет узел с таким же названием. Это гиперссылка, она пишет название существующего узла; по клику переходим в этот узел в реальном месте документа».

- **Что хранится.** Ссылка — обычный текст `[[название]]` в тексте пункта или в заметке, без id. Поэтому она читается при правке, переживает экспорт в Markdown/OPML и импорт обратно и понятна другим программам. Синхронизации и слиянию ничего нового не нужно: это обычные `setText` и `setNote`. Цена — переименование цели рвёт ссылку (см. «Не сделано»). Внутри скобок нельзя `[`, `]` и перевод строки, пустое и пробельное название ссылкой не считается (`LINK_RE` в `format.ts`).
- **Название пункта** — `titleOf(text)`: текст без маркеров жирного и курсива, без пробелов по краям. Скобки ссылок при этом остаются, поэтому пункт «см. [[Пьер]]» называется не «Пьер» и ссылку на «Пьер» не перехватывает. Сравнение — по нормализованной форме (`normalize`: регистр, ё = е).
- **Куда ведёт** — `resolveLink`: первый в порядке документа пункт с таким названием (`compareOrder` сравнивает пути от корня). Пункты в корзине не участвуют: их нет в `TextIndex`. Один проход по `TextIndex` занимает ~21 мс на 200 тыс. и выполняется только по клику.
- **Отображение.** `formatFlags` помечает символы ссылки флагом `LINK`, а скобки — ещё и `MARKER`: в обычном виде они скрыты, как маркеры жирного, а `plainText` (крошки) их выбрасывает. `decorate` даёт кускам ссылки поле `link` (название). Тег внутри ссылки — просто часть названия, а жирный, курсив и подсветка поиска внутри работают. Ссылка — цвет `--link` с подчёркиванием (новых цветов нет). При правке строка, как всегда, показывает сырой текст со скобками.
- **Переход** (`Outliner.followLink`). Клик по ссылке в обычном виде сбрасывает поиск и делает zoom в найденный пункт: крошки показывают его настоящий путь, «назад» в браузере возвращает обратно (`#/<id>`). Если пункта нет, а у структуры есть Inbox (`findInbox`: первый пункт верхнего уровня, чьё первое слово — «Inbox» в любом регистре, без учёта эмодзи, разметки, скобок ссылки и знаков вокруг — `firstWord`: «📥 **Inbox** ✅» подходит, «Inboxes» и «мой Inbox» — нет; у копии зеркала — оригинал, где лежат дети; §7о), переход создаёт пункт с этим названием последним в Inbox (один шаг undo, курсор не трогается) и входит в него; набор ссылки ничего не создаёт. Без Inbox и во вкладке только для чтения появляется сообщение «Нет пункта «…»». Переход работает и во вкладке только для чтения.
- **Набор.** `[` вторым подряд дописывает `]]` и оставляет курсор между скобками (`opensLink`; не внутри `[[[` и не перед уже стоящими `]]`). `]` перед закрывающей скобкой ссылки перешагивает её, а не вставляет новую (`closesLink`). Backspace между `[` и `]` стирает пару целиком. Это часть набора: тот же шаг отмены, что у слова. DOM правится на месте (`beforeinput`/`input` в `Row.tsx`), как для `/time`.
- **Подсказка** (`Suggest.tsx`, `findTargets`). Пока курсор внутри `[[…`, токен — от `[[` до курсора, а если пара закрыта, то до `]]` включительно (`linkBefore`, его проверяет `tokenBefore` раньше тегов): выбранное заменяет всю ссылку, поэтому можно и перенацелить готовую. Список: названия, начинающиеся с набранного, затем те, где с него начинается слово, затем остальные, внутри групп короче выше, затем свежее правленные. Пустой запрос (только что набрано `[[`) показывает последние правленные пункты. Каждое название в списке один раз. Справа серым — название родителя того пункта, куда ссылка действительно поведёт. Себя пункт не предлагает, пункты со скобками в названии тоже.
- **Скорость.** Подбор — один проход по `TextIndex`, но хранится только лучшая восьмёрка: пункт, который хуже последнего, стоит одного `indexOf` и пары сравнений, а `updated` читается только при равенстве (случайный доступ к `Map` на 200 тыс. — самое дорогое, ~85 мс за проход). Ищется в сыром тексте, поэтому маркеры оформления посреди названия могут разорвать запрос (в подсказке, не в переходе). Второй проход ищет дубликаты названий только среди уже совпавших. На синтетике 200 тыс. (много одинаковых коротких фраз): 18–55 мс на запрос, пустой запрос ~75 мс. Чтобы набор не ждал, новый запрос считается после ближайшего кадра (`requestAnimationFrame` + `setTimeout`): символ появляется за 2–9 мс, список — следом. Клавиша (Enter, ↑/↓) пересчитывает синхронно, так что берётся список к набранному. Результат запоминается, пока запрос не меняется: `selectionchange` и прокрутка его не пересчитывают.
- **Веб-адреса** (пользователь: «веб-ссылки в тексте кликабельны, и при клике на них открывается браузер»). `webLinks(text)` (`format.ts`): `http://`, `https://`, `www.` до пробела, кавычки или скобки; знаки препинания, маркеры оформления (`*`, `_`) и непарная `)` в конце в адрес не входят; `www.` получает `https://`. `formatFlags` помечает адрес флагом `URL` (32; 16 — это `HIT` поиска) вне `[[ссылок]]` и ищет жирный и курсив по тексту, где адрес заменён буквами той же длины: `_` и `*` внутри адреса не дают оформления, а жирный вокруг адреса работает. `decorate` даёт кускам `url`; `Pieces` рисует `<a class="url" target="_blank" rel="noopener noreferrer">` с «↗» после (псевдоэлемент, в текст не входит), так внешняя ссылка отличима от `[[внутренней]]`. Клик открывает адрес в браузере (в установленном приложении — в системном), строка или заголовок при этом в правку не переходят. В правке адрес — обычный текст. Теги внутри адреса не возникают: `#` и `@` там стоят не после пробела. e2e: «web addresses»; unit: `tests/format.test.ts`.
- **Обратные ссылки** (`view/Backlinks.tsx`, октябрь 2026). Пользователь: «если я перешёл из точки A дерева по ссылке, мне нужен механизм быстро вернуться обратно; если ссылок на узел больше одной и они в разных местах — перейти в любой из этих узлов через этот же механизм». Вид выбран по методу `shape` скила impeccable, пользователь выбрал из трёх вариантов: компактные плашки, переход туда, где стоит ссылка, зеркала не считаются.
  - **Модель.** `backlinks(doc, index, target)` (`links.ts`) — один проход по `TextIndex`: кандидаты — пункты, в нормализованном тексте или заметке которых есть `[[название]]`, и попутно первый пункт с таким названием. Если ссылка с этим названием ведёт в более ранний пункт (`resolveLink`), у цели бэклинков нет. Порядок — документный. `linkEnd` — смещение сразу за ссылкой в тексте пункта.
  - **Вид.** Под списком zoom, ниже «+», строка «Ссылки сюда» и плашка на каждое **место** (родитель пункта со ссылкой; ссылки из одного места — одна плашка), подпись — название места («Главная» для верхнего уровня), полный путь во всплывающей подсказке. Место, откуда только что пришли по ссылке (`Outliner.cameFrom`, записывает `followLink(title, from)`), стоит первым, помечено «←» и окрашено как тег. Больше 12 мест — «ещё N». Нет ссылок — блока нет. На сенсорном экране плашки 36 px.
  - **Переход** (`Outliner.goToBacklink`): zoom в место (или на главную), каретка на пункте со ссылкой сразу за ней (или в начале, если ссылка в заметке).
  - **Стоимость.** Поиск — проход по всем пунктам (десятки мс на 200k), поэтому он идёт после кадра с zoom и повторяется, когда правки затихли на 400 мс (подписка на commit). Высота блока меряется (`ResizeObserver`) и входит в высоту области прокрутки.
  - e2e: «backlinks» (две ссылки из разных мест, «назад» первым, переход с кареткой за ссылкой, смена «назад» после перехода из другого места; без ссылок блока нет); unit: `backlinks` и `linkEnd` в `tests/links.test.ts`.
- **Не сделано:** подсказки в заголовке zoom нет, как и для тегов (сами ссылки и теги в нём кликабельны вне правки). Переименование пункта не обновляет ссылки на него, «битая» ссылка выглядит как обычная и сообщает о себе только по клику: для обоих нужен индекс названий, а это память на каждый пункт. ## 7н. Зеркала `((…))`

Как зеркала в Workflowy (октябрь 2026, `model/mirrors.ts`). Пользователь сформулировал так: «`((` сразу создаёт пару, это зеркалирование. Создаётся как гиперссылка, но по факту создаёт зеркальную копию узла: с ним можно работать там, где он описан через `(( ))`, и изменения происходят синхронно во всех местах документа. У зеркал другой значок — ромбик».

- **Что хранится.** В отличие от ссылки, зеркало — свойство пункта, а не текст: `OutlineNode.mirrorOf` хранит id оригинала (название не годится: правка через зеркало меняет сам текст). Операция `setMirror {id, from, to}` обратима; снимок v5 добавляет колонку `mirror`. В слиянии `setMirror` применяется, если значение отличается; синхронизации больше ничего не нужно.
- **Что показывает строка.** `Doc.content(id)` — пункт, чьи текст, заметку и состояние задачи показывает строка: оригинал для зеркала (сам пункт, если оригинал вычищен из корзины), иначе она сама. `Row.tsx` читает текст и заметку через `content()` и подписывается на сигналы обоих узлов (`acquire` оригинала на время жизни строки), поэтому правка в любом месте перерисовывает все зеркала. Собственные текст, заметка и флаги зеркала не используются.
- **Правки.** Команды содержимого (`setText`, `setNote`, `toggleDone`, `cycleTask`, `untask`, `insertTrees`, `Outliner.insert`, `format`) переадресуют на `doc.content(id)`, а структурные (`split`, `indent`, `move*`, `deleteNode`) работают с самой строкой.
- **Все копии равноправны** (доработка; пользователь: «После создания зеркала обе ноды становятся зеркалами (иконка ромбика у обоих). Нет понятия оригинала и зеркала. Если удалить одно из зеркал — оставшаяся нода станет обычным узлом. Если было создано несколько зеркал, то пока существует хотя бы 2 зеркала — они остаются зеркалами и меняются синхронно»). Прежнее правило «заголовок зеркала только для чтения» (`mirrorHeading`, `Outliner.mirrorReadOnly`, `restore`) снято: `setText`, `setNote`, `split`, вставка, `/time`, Ctrl+B/I, заметка правят `doc.content(id)` из любой копии. Хранение прежнее — данные лежат в одном пункте (origin), остальные копии ссылаются на него через `mirrorOf`; так проще слияние и undo, а в интерфейсе разницы нет. `Doc.copies(id)` — origin и все пункты, чья цепочка зеркал ведёт к нему, в документе (обратный индекс `mirrored`: цель → зеркала, ведётся в `insert`/`remove`/`setMirror`); `Doc.isCopy(id)` — копий две и больше: тогда ромбик у каждой (`Row.tsx`, реактивно через `rowsVersion`). Осталась одна — обычный пункт.
- **Удаление копии.** Backspace в начале любой копии, Ctrl+Shift+Backspace, удаление выделения убирают только эту копию. Если уходит origin (или поддерево, где он лежит), `handOver` в `commands.ts` до переноса в корзину передаёт первой по документу оставшейся копии всё: снимает с неё `mirrorOf`, переписывает текст, заметку, задачу, переносит детей с теми же ключами порядка и перенаправляет на неё остальные копии. Это обычные операции в той же транзакции: один шаг undo, синхронизация и слияние без нового кода. Строки, адресованные ключом под исчезнувшим зеркалом, `locate` находит по id.
- **Зеркало показывает всё поддерево оригинала** (доработка того же дня; пользователь: «зеркало показывает не только сам узел, на который ссылается, но и все узлы ниже до самого последнего. Зеркало позволяет включать разные участки дерева без необходимости держать несколько вкладок»). Своих детей у зеркала по‑прежнему нет: под ним показываются дети оригинала, это те же пункты, а не копии. Правка, удаление, перенос пункта внутри зеркала меняют его в оригинале и во всех зеркалах сразу.
- **Ключ строки.** Один пункт теперь виден в нескольких строках, поэтому строки в `VisibleRows`, фокус, выделение, перетаскивание и компоненты `Row` адресуются ключом строки (`RowKey`, `model/rows.ts`), а не id. Вне зеркал ключ равен id; под зеркалом — ключ строки зеркала, `/` и id (`m/x`, для зеркала в зеркале `m/m2/x`). `nodeOf(key)` — последний сегмент, `contextOf(key)` — всё до него, `keyIn(context, id)` — обратно; в id от nanoid символа `/` нет. Сигналы узлов (`NodeSignals`) и индексы по‑прежнему по id.
- **Строки.** `VisibleRows.host(key)` — чьи дети показываются под строкой: сам пункт, у зеркала — оригинал (`Doc.host`, через цепочку зеркал). `shownChildren`, `showsChildren`, `hasHiddenChildren` принимают ключ. `collect` при обходе переключает контекст на ключ зеркала, `parentKey(key)` даёт строку‑родителя по виду (для строки прямо под зеркалом — само зеркало). Зеркало сворачивается своим флагом `collapsed`, отдельно от оригинала.
- **Свёрнутость у каждой копии своя** (пользователь: «если я редактирую одно зеркало… и раскрываю, скрываю элементы — другие зеркала при этом меняются, но не раскрываются или сворачиваются синхронно с моими действиями»). Пункт под зеркалом — это тот же пункт, поэтому его флаг `collapsed` общий; вид под каждым зеркалом хранит `VisibleRows.folds`: `зеркало/пункт` → свёрнут, без записи — как флаг пункта (`folded(key)`). Сворачивание под зеркалом (`setCollapsed` с ключом в контексте, `unfold` в Tab/перемещениях/перетаскивании) меняет только запись и все строки этого зеркала в списке; операции нет, в историю отмены не попадает. Сворачивание там, где пункт лежит, — прежняя операция `setCollapsed`, но сначала `freeze` записывает текущий вид во все зеркала пунктов выше него, у которых записи ещё нет: другие копии не меняются. Записи живут на устройстве (`Outliner.keepFolds`, `localStorage` `listik-folds:<имя базы>`, как и само сворачивание, они не синхронизируются); при загрузке записи исчезнувших зеркал отбрасываются (`loadFolds`). Рандомизированный тест сверяет строки с пересборкой, которой переданы те же записи.
- **Патчи.** `VisibleRows.mirrors` — ключи строк‑зеркал в списке, то есть контексты, где пункт может быть виден ещё раз. Каждая операция патчится в каждом контексте (`''` и все зеркала): `show`/`hide`/`refreshAll`. Без зеркал на экране контекст один, и стоимость прежняя. Дополнительно: `setMirror`, вставка и удаление пункта перестраивают строки зеркал, чья цепочка через него проходит (`refreshMirrorsOf`), а перенос — строки зеркал, у которых один из сегментов ключа оказался внутри перенесённого (`refreshMirrorsIn`: от этого зависит петля, см. ниже). Рандомизированный тест (`tests/mirrors.test.ts`, три режима: обычный, zoom, фильтр) сверяет строки с полной пересборкой, уникальность ключей и `parentKey` каждой строки; прогнан на 300 сидах.
- **Петли.** Зеркало внутри того, что оно отражает (прямо или через другие зеркала, в которых показано), показало бы само себя бесконечно. `host(key)` проверяет каждый сегмент ключа: если оригинал содержит его, детей у этой строки нет. Конечность обхода доказывается так: бесконечная цепочка повторила бы зеркало, а значит его оригинал содержал бы один из сегментов.
- **Команды и фокус.** Команды принимают ключ и берут пункт через `nodeOf`. Детей под зеркало кладут к оригиналу (`hostFor`): Tab под зеркало, перемещение вверх/вниз и перетаскивание в него, Enter в конце раскрытого зеркала (новый пункт — первый ребёнок оригинала), вставка дерева. Shift+Tab и перемещение за край родителя считаются по виду: пункт прямо под зеркалом выносится к соседям зеркала. Пункт нельзя положить внутрь себя через зеркало. Команда, которая переносит строку, возвращает её новый ключ, и `Outliner.run` оставляет каретку на том же месте текста. Новый пункт команда называет по id, а `VisibleRows.locate(id, near)` находит его строку ближе всего к каретке: в том же зеркале, в объемлющих, вне зеркал, затем в любом. Выделение, захватившее и пункт, и его зеркало, действует на каждый пункт один раз (`blockOf`).
- Zoom в зеркало (точка, Alt+→) ведёт к оригиналу (`Doc.origin`).
- **Создание.** `((` закрывается до `(())`, `)` перешагивает скобку, Backspace между `(` и `)` стирает пару (те же механизмы, что у `[[`, в `Row.tsx`). Подсказка — тот же `findTargets` с токеном `((` (`mirrorBefore`, в `tokenBefore` после ссылки), без самого пункта и его оригинала; в заметке `((` — просто скобки. Выбор не вставляет текст, а вызывает `makeMirror`: пустой пункт (без заметки и детей) становится зеркалом; иначе токен уходит из текста, а зеркало встаёт следующим соседом. Зеркало зеркала указывает на оригинал; пункт не может зеркалить себя (`Doc.apply` бросает).
- **Зеркало того, чего ещё нет** (по просьбе пользователя: «если создаёшь новое зеркало и такой ноды нет, оригинал автоматически создаётся в Inbox, а здесь появляется активное зеркало»). Если у структуры есть Inbox (`findInbox`, §7о), а среди подсказок нет пункта ровно с набранным названием, последней строкой идёт «Создать «название» в Inbox». Второй путь — допечатать `))` самому: последний `)` (`beforeInput` в `Row.tsx`, только в тексте пункта) вызывает `Outliner.mirrorTitled`. Он берёт первый пункт с таким названием (`resolveLink`), а если его нет — создаёт оригинал последним в Inbox; затем `makeMirror`. Всё — один шаг undo, курсор остаётся у зеркала, перехода нет. Без Inbox и без такого пункта, а также для самого пункта `((…))` остаётся текстом.
- **Удаление** (подробно выше). Если выделение захватило копию вместе со строками под ней, строки под зеркалом в блок не входят (`blockOf` отбрасывает ключи, у которых выделенное зеркало — контекст), поэтому пункты остаются в другой копии. Delete в конце строки над копией её не втягивает; текст строки ниже Backspace склеивает с копией выше, как с любым пунктом (меняется во всех копиях). В документах до этой доработки origin мог уйти в корзину без передачи: такое зеркало показывает его до чистки корзины, после — пустое с подписью «Оригинал этого зеркала удалён» (`.row.orphan`).
- **Вид.** Точка зеркала — ромбик 7 px тем же кораллом (`.bullet.mirror`); у зеркала‑задачи остаётся чекбокс, а маленький ромбик стоит у его угла. Экспорт в Markdown и OPML пишет зеркало как копию оригинала (`doc.content`), импорт обратно даст копии: ожидаемо для внешних программ. Индексы тегов и поиска видят только оригинал (у зеркала свой текст пуст), поэтому совпадение показывается один раз.
- Тесты: unit `tests/mirrors.test.ts` (токен и пара, пустой пункт становится копией и правится из любой, обе с ромбиком, зеркало под текстом, цепочка и само‑зеркало, дети под зеркалом идут к оригиналу, Backspace в любой копии, передача при удалении origin, три копии и undo, старое зеркало без передачи, undo и слияние, снимок v5 и экспорт; поддерево под зеркалом, правки в обе стороны, Enter, Shift+Tab и ↑ из зеркала, своя свёрнутость у копий и `freeze`, Tab в свёрнутый под зеркалом, петли, выделение; рандомизированный тест в четырёх режимах); e2e «mirrors» (`((` закрывается, подсказка, ромбик у обеих копий, правка из любой, точка ведёт туда, где пункт лежит; копия показывает всё поддерево, Enter внутри неё оставляет каретку там же, пункт свёрнут в одной копии и открыт в другой, Backspace в начале убирает только эту копию; удаление копии с данными и undo; свёрнутость под копией после перезагрузки; удаление выделения с зеркалом и его строками оставляет оригинал целым; зеркало под текстом, `)` перешагивает, Backspace стирает пару; зеркало несуществующего пункта — подсказкой «Создать … в Inbox» и закрытием `))`, undo).
- Ограничения: поиск и фильтр находят пункт в оригинале, зеркало в выдачу не попадает; экспорт и копирование пишут зеркало одной строкой (без поддерева оригинала, чтобы не дублировать и не зациклиться); скрытие выполненных не прячет зеркало выполненной задачи.

## 7с. Задачи внутри пункта

- **Три состояния по Ctrl+L** (пользователь: «у чекбокса при клике два статуса. Но по сочетанию клавиш Ctrl+L или на клавиатуре на мобилке уже 3 статуса: добавить чекбокс, отметить выбранным, удалить чекбокс. Все трое меняются по кругу»): `cycleTask` — обычный → задача → выполнена → обычный; на нескольких: сначала обычные становятся задачами, затем открытые отмечаются, затем все снимаются (`untask`). Клик по чекбоксу — по-прежнему `toggleDone`, только отметка.

Пользователь, октябрь 2026: «Если внутри ноды есть незавершённые задачи с чекбоксом — то под нодой (в поле Shift+Enter) выводится содержимое этого чекбокса и иконка… Так я могу быстро понять, что внутри ноды есть задачи к выполнению без открывания каждой ноды. Работает как со ссылками, так и с зеркалами… Если я завершаю чекбокс внутри ноды, но там есть ещё — берётся первый (сверху)»; и: «у этих нод может быть уже что-то написано. В таком случае текст надо опустить строго вниз на строку и выше написать инфу про задачи».

- **Индекс** (`model/tasks.ts`, `PendingTasks`): множество открытых задач (`todo && !done`, не зеркала — их состояние у оригинала) по операциям; версия растёт только когда операция касается открытой задачи (её состояние; вставка, удаление, перенос поддерева с ней). Набор текста, Enter и перенос обычных пунктов индекс не трогают. По запросу после изменения — счётчики «сколько открытых внутри» одним проходом вверх от каждой задачи; первая сверху — только для спрошенного пункта, спуском по веткам со счётчиком (`firstBelow`), с кэшем. Замер: 200 тыс. пунктов, 5 тыс. открытых задач — 3,5 мс на пересборку и 40 строк. Рандомизированный тест сверяет с полным обходом.
- **Что показывать** (`Outliner.pendingFor`, реактивно по `tasksVersion` и `rowsVersion`): первая открытая задача внутри пункта (у зеркала — внутри оригинала), пока его дети не видны (свёрнут или скрыт поиском); иначе — по `[[ссылкам]]` в тексте: сам пункт ссылки, если он открытая задача, или первая внутри него. Куда ведёт ссылка — `resolveLink` с кэшем (`linkCache`: найденный проверяется, промах живёт до следующей версии задач). Раскрытый пункт подсказки не показывает: задачи видны в списке.
- **Вид** (`Row.tsx`, `.pending`): одна строка между текстом и заметкой, размером заметки: коралловый пустой квадратик (единственный акцент — «есть что сделать»), текст задачи цветом туши (действие, отличается от приглушённой заметки ниже), «+N» бледно; обрезается многоточием, не переносится — список не распухает. Квадратик — `completeTask` (одна отметка, шаг undo; следующая встаёт на место), текст — `goToTask` (zoom в родителя, курсор в конец задачи). Текст задачи следит за её правками (сигнал узла держится, пока строка видна).
- Тесты: unit `tests/tasks.test.ts` (первая сверху и число, отметка, удаление; рандомизированный против обхода с undo); e2e «open tasks under a bullet» (свёрнутый — задача над заметкой, отметка ведёт к следующей, раскрытый — нет, undo; ссылка и зеркало, переход к задаче).

## 7р. Шаблоны

Пользователь, октябрь 2026: «Шаблон — это нода с обязательным тегом #template. После этого Listik считает саму ноду с тегом и все вложенные элементы частью шаблона. Название шаблона — содержимое ноды. Дальше в любом месте дерева через команду /template можно выбрать из выпадающего списка нужный шаблон. После выбора — он добавляется или в текущую ноду (если она пустая) или в следующую по порядку на одном уровне». Логика — `model/templates.ts`.

- **Что шаблон.** `findTemplates`: пункты с `#template` в собственном тексте (не в заметке; не зеркало), по `TagIndex`, в порядке документа; корзина не видна. Название — `templateTitle`: текст без тега, без разметки.
- **Подсказка.** Шаблоны идут в той же подсказке `/`, что и команды (`Suggest.tsx`), после команд, кроме того шаблона, в котором набирают: `matchTemplates` даёт все, пока набранное может стать `/template` (`/`, `/t`, `/temp`), по названию после `/template`, или по названию сразу после `/` (`/встр`). В заметке шаблонов нет (шаблон — пункты). Шаблонов нет — строка «Шаблонов нет: пометьте пункт #template» (ничего не делает).
- **Вставка** (`insertTemplate`, `Outliner.insertTemplate`, один шаг undo): только содержимое шаблона — дети `templateTree` (заметки, задачи, всё поддерево; зеркало внутри — копией того, что показывает; все задачи без отметки), без самого пункта-заголовка с `#template` и на уровне строки, где набрали команду (доработка; пользователь: «вставляются только символы внутри этого шаблона без шапки с тегом template… на 1 уровне, без сдвига»). Пустая строка (без другого текста, заметки и детей) принимает первый пункт (его текст, заметку, задачу, детей — к ней, у зеркала — к оригиналу), остальные встают следом; иначе токен уходит из текста, и всё встаёт после строки. Курсор — в конец первого вставленного. Пустой шаблон только убирает токен и говорит об этом. Вставка — `placeTrees`, большие шаблоны пересобирают строки один раз.
- Тесты: unit `tests/templates.test.ts` (поиск и названия, заметка и корзина, сопоставление запроса, копия без отметок, вставка содержимого без заголовка в пустой и в непустой пункт, пустой шаблон); e2e «templates» (`/встр` в пустом пункте — содержимое на его уровне, `/template` в пункте с текстом — следом, undo; без шаблонов — подсказка).

## 7п. Быстрая запись в Inbox

Пользователь, октябрь 2026: быстрая запись в Inbox, «чтобы записать что-то в моменте и потом обработать», вместо панели-дерева слева (сделана и убрана после пробы: неудобна). Паттерн выбран через `impeccable shape` и двух агентов-рецензентов (дизайнер взаимодействия и эвристики Нильсена): Quick Entry как в Things / Quick Add в Todoist. Ответы пользователя: чаще на компьютере, короткая мысль в строку, счётчик не нужен, запись — в конец Inbox, на телефоне вход только через меню, первым пунктом.

- **Не «+».** «+» в Listik значит «добавить здесь» (под списком, «⊞» в панели правки); запись уходит в другое место, поэтому метафора другая — лоток входящих, и место другое — шапка (глобальное), а не список (локальное). Ошибка режима «куда ушла мысль» снята подсказкой «Мысль → Inbox» и сообщением «Записано в Inbox · Отменить».
- **Вход.** Ctrl+Shift+Space (по `code`: любая раскладка; ловится до проверки «правится ли строка», поэтому работает и во время правки), значок `.capture-button` в шапке (скрыт на ≤ 640 px), пункт меню «Записать в Inbox» — первым.
- **Строка** (`QuickCapture.tsx`): не модальная (без затемнения, список не сдвигается), на компьютере под шапкой, на телефоне — лист над клавиатурой (`enterkeyhint="send"`). `/time` заменяется временем, теги и ссылки — это просто текст. Enter — `Outliner.capture`, Esc или уход из строки — закрыть с черновиком (`captureDraft`).
- **Запись** (`Outliner.capture`): последним в Inbox (`findInbox`, §7о; нет — пункт «Inbox» в конце верхнего уровня), одна транзакция и шаг отмены, мимо `run`: ни фокус, ни zoom, ни прокрутка основного списка не трогаются. «Отменить» в сообщении (`notify(message, action, link)`, `toastAction`) применяет обратные операции этой записи; «Inbox» в нём (`toastLink`, пунктирное подчёркивание — слово-ссылка внутри фразы) ведёт к записанному: zoom в Inbox, курсор в конец записи (`goToTask`), сообщение закрывается — чтобы сразу дописать. Сообщение внизу по центру шириной по содержимому (`width: max-content`, не шире окна без 32 px): одно `left: 50%` оставляло ему половину окна, и на телефоне «Записано в Inbox · Отменить» ломалось на две строки.
- **Место курсора.** `openCapture` читает настоящую позицию каретки со страницы (запрос фокуса — место начала правки, набор ушёл дальше), `closeCapture` возвращает её.
- Тесты: e2e «quick capture» (клавиша во время правки, `/time`, Inbox создаётся и пополняется в конец, каретка возвращается, значок в шапке, «Отменить»; Esc и черновик) и «quick capture comes first in the menu…» (телефон: первый пункт меню, лист внизу, значка в шапке нет).

## 7о. Структура и календарь

Структура в духе PARA с календарём по кварталам — по заданию пользователя (октябрь 2026), вместо прежнего вечного календаря без лет по образцу Forever Notes. Логика — `model/calendar.ts`, без DOM.

- **Структура** — девять пунктов верхнего уровня с заметками (`STRUCTURE`): Inbox, `@q1`…`@q4`, Projects, Hubs, Reference, Archive. Кварталы свёрнуты, в каждом текущий год. Появляется:
  - при первом запуске нового документа (`Persistence.open` → `fresh`, `Outliner.firstStructure(true)` в `App.tsx`) на месте единственной пустой строки, без шага undo;
  - при «Новый документ на сервере» (`SyncDialog`, `firstStructure(false)` до `createSync`), если на верхнем уровне нет ни одного квартала, одним шагом undo — поэтому структура уходит уже в снимок № 0; при подключении к существующему документу не создаётся;
  - по кнопке меню «Создать структуру» (`Outliner.createStructure`): всегда, в конец верхнего уровня, одним шагом undo, затем «Сегодня». Вторая структура ничего не ломает: календарём остаётся первая (`findQuarter` берёт первый по документу).
  - `?empty` (`Outliner.bare`) отключает оба автоматических случая: с одной пустой строки начинают e2e-тесты.
- **Календарь — только теги** (так решил пользователь): `@q4` (верхний уровень) → год `@y2026` → `@m10` → неделя `@w43` → день `@d19 @m10 @понедельник`. Числа двузначные: тег в поиске совпадает по началу, и `@m1` нашёл бы `@m10`. В дне есть месяц, потому что фильтр проверяет теги каждого пункта отдельно; года в дне нет, поэтому `@d19 @m10` находит этот день во все годы. Недели — ISO 8601 (`isoWeek`): с понедельника, неделя 1 содержит первый четверг. Неделя на стыке месяцев есть в обоих месяцах, у каждой свои дни (`weeksOf`); дни конца декабря бывают в `@w01`, дни начала января — в `@w53`.
- **Год создаётся целиком** (`yearTree`: 3 месяца, ~15 недель, ~92 дня в квартале, ~440 пунктов за год, дни свёрнуты): текущий — со структурой, остальные — `addYear` при первом попадании в год («Сегодня», ‹ ›), во все кварталы, где его нет, по порядку лет. Одной операцией `insert` на квартал (`placeTrees`), один шаг undo.
- **Шаблон дня** (`dayTemplate`, `fillDay`): `#notes` и `todo`, под каждым — пустой обычный пункт (раньше под `todo` была задача-чекбокс; пользователь: «в блоке todo не создавать чекбокс. Оставить просто один пункт, как в поле выше — notes»), 19 слотов `09:00`…`18:00` — 23 пункта. Ставится в `Outliner.zoomTo` (`enterDay`) при любом входе в день, у которого ещё нет детей: «Сегодня», ‹ ›, клик по точке, ссылка, крошки, адрес. Отдельный шаг undo; курсор не ставится (шаг не трогает фокус: `keepFocus`). На вкладке только для чтения не ставится. Часы создаются только в посещённых днях: год с часами во всех днях был бы ~7 400 пунктов.
- **Поиск периода — по тегам и окружению, а не по месту.** `labelOf` читает собственные теги пункта (день, неделя, месяц, год, квартал); `periodAt` добирает год (и для недели месяц) из предков и требует квартал на верхнем уровне. Пункт внутри периода того же или более мелкого ранга периодом не считается: запись «созвон @d24 @m10» в другом дне не станет 24 октября. `findPeriod` — пересечение `TagIndex.nodesWith` по тегам периода (без дня недели), фильтр по `periodAt`, из нескольких — самый верхний, среди равных первый по документу. Поэтому дни можно переименовывать («@d19 @m10 @понедельник день рождения»), снабжать заметкой и переносить в другую неделю.
- **Сегодня** — `Outliner.goToday`: логотип (`TopBar.tsx`), запуск без `#/…` в адресе (`Outline.tsx`, сразу после `syncZoomWithHash`) и после «Создать структуру». Находит день по дате устройства (`dayOf`), при надобности создаёт год (`periodBullet`), сбрасывает поиск и входит в день. Без структуры — подсказка про меню, `quiet` (запуск) молчит.
- **Синхронизация.** Пока сервер с запуска не ответил (`synced` в `Outliner`: фазы `synced`/`offline`/`error`, без синхронизации — сразу), ни год, ни шаблон дня не создаются, а ждут в `afterSync` (список). Иначе устройство, не получившее чужой год или шаблон, завело бы второй; слияние их не склеивает. Отложенное выполняется, только если пользователь всё ещё там же.
- **Наутро.** `goToday` запоминает день и дату; `Outliner.resumed` на `visibilitychange` ведёт в новый день, если вкладка всё ещё в старом.
- **Соседние периоды.** `Outliner.zoomPeriod` (реактивно) — период, в который вошли (`periodAt`): день, неделя, месяц или год квартала (`kind: 'quarter'`). Тогда в конце строки крошек стоят ‹ › (`PeriodSteps` в `ZoomHeader.tsx`). `stepPeriod` идёт по `neighbour`: дни через месяцы и годы, недели — как они лежат в документе (неделя на стыке — дважды), месяцы, кварталы года. Недостающий год создаётся; отсутствующие иначе периоды пропускаются, не больше 400 шагов. Клавиши Ctrl+Alt+←/→ (`periodKeys` в `keymap.ts`) работают в строке, заметке, заголовке и вне правки и проверяются раньше Alt+←. На самих `@q1`–`@q4` стрелок нет: в них все годы.
- **Главная.** Прежнее действие логотипа (`goHome`: выйти из zoom и поиска, свернуть верхний уровень, один шаг undo) — на крошке «Главная» на главной странице; из zoom «Главная» только выходит на главную.
- **Старый вечный календарь** (`@календарь`) в документах остаётся обычными пунктами: его квартал не на верхнем уровне, а год внутри дня — внутри более мелкого периода, поэтому `periodAt` его не видит.
- Тесты: unit `tests/calendar.test.ts` (недели ISO, дерево года и структуры, создание в конец и дважды, поиск периодов по годам, записи-двойники, переименование и перенос, соседи через годы и стыки недель, `addYear` по порядку и undo, `fillDay`), e2e «structure and calendar» в `e2e/outline.spec.ts` (меню: структура в конце, сегодня с шаблоном без курсора, undo; логотип без структуры и с ней, повторно ничего не создаётся; ‹ › и Ctrl+Alt+стрелки по дням, неделям, месяцам и кварталам; новый документ начинается со структуры на сегодня, перезагрузка остаётся на месте) и «Главная» сворачивает верхний уровень, в том числе на 200k.

## 8. Хранение (IndexedDB)

**Схема: snapshot + журнал операций.**
- `meta/snapshot` — одна запись со всем документом в pre-order: `[id, parentIdx, order, text, collapsed, created, updated][]`. Pre-order означает, что дети приходят по порядку и сортировать при загрузке не нужно. Для 5 млн знаков ≈ 7–8 МБ JSON, `JSON.parse` ≈ 30–60 мс.
- `oplog` — пачки ops с автоинкрементным ключом, накопленные после snapshot.

**Запись** (`src/persist/idb.ts`): ops копятся в памяти и сбрасываются одной транзакцией через 300 мс после первого, а также на `visibilitychange: hidden` / `pagehide`. Подряд идущие `setText` одного bullet'а схлопываются в одну операцию. Стоимость сохранения правки не зависит от размера документа. При аварии теряется не больше последних 300 мс.
**Компакция** (с M4, `src/persist/compact.ts` в `compact.worker.ts`): когда в журнале > 10 000 ops, Web Worker в одной транзакции читает снимок и журнал до последнего ключа K, применяет журнал, затем в другой транзакции пишет новый снимок и удаляет записи с ключами ≤ K. Главный поток только дописывает журнал. Записи, добавленные во время компакции, получают ключи > K, остаются в журнале и применяются поверх нового снимка, поэтому счётчик поколений из M2 больше не нужен. Без Worker (unit-тесты в Node) та же функция работает в процессе. Рандомизированный тест правит документ, пока идут компакции; мутационная проверка (удалять весь журнал вместо ≤ K) этим тестом ловится.
**Загрузка:** читаем snapshot (прямое заполнение `Map`, без ops), применяем журнал, строим VisibleRows. Если операция журнала не применяется, загрузка падает с ошибкой, а данные в базе остаются нетронутыми. Молча отбрасывать хвост журнала нельзя.
**Защита от вытеснения:** `navigator.storage.persist()`.
**Параметры URL:** `?db=имя` — выбрать базу (тесты, бенчмарк). `?demo` и `?sample=N` — документы только в памяти, сохранённые данные они не трогают.

**Замеры M2** (Chromium 152, 200 тыс. bullet'ов, 9 млн знаков — втрое больше «Войны и мира»):

| Операция | Время |
|---|---|
| Загрузка (snapshot + журнал) | 343 мс |
| Применить правку | 0,2 мс |
| Сохранить одну правку | 1 мс |
| Компакция (сериализация 154 мс + запись) | 456 мс, блокирует main thread (в M4 перенесена в Worker: пауза 4–5 мс) |

Резерв на будущее: снимок без UUID-подобных id и с временем в секундах. 26 млн символов JSON на 9 млн знаков текста — в основном служебные поля.

**Одна пишущая вкладка** (`src/persist/lock.ts`). Вкладка, первой получившая Web Lock `listik:<база>`, держит его всю свою жизнь и одна пишет в базу. Остальные вкладки с тем же документом:
- читают его без записи (`Persistence.read`);
- показывают плашку «только просмотр»;
- не дают ничего менять: `Outliner.readOnly` блокирует команды, набор и undo, а строки и заголовок не становятся редактируемыми;
- не показывают «+», импорт и автокопию.

Экспорт, поиск и zoom работают. Когда пишущая вкладка закрывается, ожидающий запрос блокировки срабатывает, и вкладка перезагружается уже как пишущая. Это безопасно: в режиме просмотра нечего терять. Без Web Locks (очень старые браузеры) пишут все вкладки, как раньше.

Почему не по записи на узел: `getAll()` на 200 тыс. записей — это секунды на холодном старте, плюс тысячи мелких записей. Почему не SQLite-WASM/OPFS: +1 МБ wasm и сложная настройка ради FTS, который в MVP не нужен. Если понадобится, вернёмся к этому вместе с поиском.

## 9. Масштаб и запасные ходы

- Если 1 млн узлов не поместится в бюджет памяти: struct-of-arrays (целочисленные индексы, `Int32Array` для parent/firstChild/nextSibling, тексты в отдельном массиве строк). API `Doc` при этом не меняется.
- Память: ~450 байт на bullet (91 МБ на 200 тыс.). Около 1 млн bullet'ов это уже ~450 МБ, и тогда понадобится struct-of-arrays (выше). Мелкие резервы (общий пустой `children[]` у листьев, компактные метки времени) дают по 3–5 МБ и не стоят тонких инвариантов в ядре.
- Если загрузка станет узким местом: разбирать снимок в Worker и передавать главному потоку уже готовые колонки (typed arrays).
- Синхронизация сделана (§7к): журнал на сервере, перебазирование и слияние на клиенте. Если документ дорастёт до того, что снимок станет тяжёл для выгрузки с телефона, снимки можно делать реже или в Worker.

**Массовые транзакции.** Если транзакция содержит больше `PATCH_LIMIT` = 16 операций (сворачивание сотен пунктов, длинная вставка, отмена таких команд), `VisibleRows` перестаёт патчить по одной и один раз пересобирает список на commit (и после отката). Команда, которая заранее знает, что операций будет много, вызывает `rows.expectMany()` (`collapseChildren`, `insertText`). Тогда точечных патчей нет вовсе: каждый из них на 200 тыс. строк стоит ~2 мс из-за пересборки раскладки виртуализатора. Под фильтром режим не включается — там патчи нужны, чтобы правленые строки оставались видимыми. Команды читают строки только до своих первых операций, поэтому устаревший список посреди транзакции они не видят.

**Заметки по M1:**
- `VisibleRows` сообщает подписчикам о каждом splice (`RowsListener`). Виртуализатор держит массив высот параллельно строкам и после структурной операции перестраивает дерево Фенвика за O(n), на 200 тыс. строк это ~1 мс. Замер высоты одной строки стоит O(log n).
- Фокус хранится как состояние (`Outliner.focus`), а не как DOM-фокус. Строка в фокусе рендерится как `Editable`, а при прокрутке назад монтируется заново и снова получает фокус. Потеря DOM-фокуса фокус не сбрасывает. Сбрасывают его Esc и скрытие строки (свернули родителя).
- Нативный undo в contenteditable заблокирован до M2: он рассинхронизировал бы DOM и модель.
- `insertText` (вставка из буфера) добавляет строки по одной, это O(k·n) для k строк в документе из n строк. Для реальных вставок (до сотен строк) этого достаточно. Массовый импорт не входит в сценарий (§1), и бенчмарк M4 строит документ сразу через `insert` поддеревьев (`src/dev/sample.ts`).

## 12. Известные риски

- **contenteditable** — главный источник багов: каретка, IME, вставка, Safari. Держимся инварианта «один text node» и `plaintext-only`. Нужны e2e-тесты (Playwright) на клавиатурные сценарии.
- **Переменная высота строк + виртуализация** — скачки скролла. Нужны якорь скролла и правильная оценка высоты, например по длине текста.
- **Вытеснение данных браузером** без `storage.persist()`. Экспорт в файл стоит сделать сразу после MVP.
- **Код из сети.** Веб-приложение не может защититься от подмены своего кода тем, кто контролирует его хостинг; поэтому код и данные разнесены (§7л). Забытый пароль синхронизации восстановить нельзя: ключ есть только у того, кто его знает.
- **Компакция пропускает чистку корзины между устройствами.** Чистка локальна; устройство, не выходившее на связь дольше 30 дней, может «воскресить» пункт из своей корзины правкой — он придёт как `insert` под отсутствующего родителя и ляжет в корзину получателя. Это видно только в корзине.
