# Listik — архитектура MVP

Outliner в стиле Workflowy: один бесконечный bullet-список. Главная фича — мгновенная фильтрация по `#tag` на документе объёмом «Война и мир» и больше.

## 1. Требования и бюджеты

**Функции MVP:** добавить / удалить / редактировать bullet, вложить (Tab), вынести (Shift+Tab), подвинуть вверх/вниз, свернуть/развернуть, undo/redo, клик по `#tag` → фильтр.

**Объём.** «Война и мир» ≈ 3 млн знаков. Если бить на bullet'ы по абзацам, выйдет ~25 тыс., по предложениям — ~150 тыс. Целевой бенчмарк: **200 тыс. bullet'ов, 5 млн знаков, глубина до 20**. Запас прочности: 1 млн bullet'ов, если понадобится, переходим на struct-of-arrays (см. §9).

**Сценарий роста.** Такой объём набирается постепенно, внутри приложения, за месяцы и годы. Массовая вставка всего текста разом — не сценарий. Требование другое: когда документ дорос до этого размера, всё должно работать так же быстро, как на пустом. Это ввод и структурные правки, фильтр по `#тегу`, поиск по тексту, запуск и сохранение. Поэтому стоимость каждой операции не должна зависеть от размера документа (или зависеть очень слабо). Сохранение пишет только изменения, а не весь документ.

| Операция | Бюджет |
|---|---|
| Операция | Бюджет | Факт: 67 тыс. (≈ «Война и мир») | Факт: 200 тыс. |
|---|---|---|---|
| Нажатие клавиши: работа (обработчик + вёрстка), p95 | < 16 мс | 1,1 мс | 1,7 мс |
| Enter / Tab: работа, p95 | < 16 мс | 3,6 / 2,4 мс | 4,7 / 4,8 мс |
| Клик по `#tag` → кадр | < 50 мс | 18 мс | 32 мс |
| Ввод в поиск → результат на экране | < 50 мс + кадр | 29 мс | 53 мс |
| Холодный старт: первая строка на экране | < 1 с | 324 мс | 666 мс |
| Память: документ + индексы | < 200 МБ | 50 МБ | 91 МБ |
| Самая долгая пауза главного потока при пересборке снимка | — | 4,5 мс | 4,4 мс |

Все бюджеты выполнены (`npm run bench`, полные таблицы — в `bench/RESULTS.md`).

**Память на 200 тыс. bullet'ов:**

| Часть | Память |
|---|---|
| Документ | 63 МБ |
| Строки и теги | 3 МБ |
| Копия текстов для поиска | 24 МБ |
| **Итого** | **91 МБ** |

Прежняя цифра 188 МБ была ошибкой замера: бенчмарк держал в куче и сгенерированный документ, и только что записанный в IndexedDB снимок. Попутно найдена настоящая утечка, она исправлена: V8 отдаёт длинные строки из `JSON.parse` срезами исходной строки, поэтому каждый текст и id держал весь 26-мегабайтный снимок. Копирование строк при загрузке (`src/util/own.ts`) сократило документ со 113 до 63 МБ ценой ~70 мс загрузки.

**Платформа:** веб (PWA), данные только локально. Модель операций спроектирована так, чтобы синхронизацию можно было добавить позже.
**Стек:** TypeScript + SolidJS + Vite, Vitest для тестов.

## 2. Главные принципы

1. **Модель отделена от реактивности.** 200 тыс. узлов не кладём в Solid store (прокси слишком дорогие). Документ — обычные JS-объекты в `Map`. Solid видит только узкие сигналы (§6).
2. **В DOM только видимое.** Дерево разворачивается в плоский список видимых строк, и рендерится только окно вокруг viewport (~50–100 строк).
3. **Все изменения — операции.** Любая мутация — это `Op`. Операции нужны для undo/redo, для журнала на диске и, в будущем, для синхронизации.
4. **Индексы обновляются инкрементально.** Правка одного bullet'а стоит O(длина его текста), а не O(весь документ).

```
┌──────────────── view (Solid) ─────────────────┐
│ Outline → Virtualizer → Row (static | editing)│
│ keymap.ts → commands                          │
└───────────────▲───────────────────┬───────────┘
   сигналы      │                   │ commands
┌───────────────┴───────────────────▼───────────┐
│ model: Doc ◄─ ops ─ commands       history    │
│        │                                      │
│        ├─► TagIndex (Map<tag, Set<id>>)       │
│        └─► VisibleRows (flat pre-order list)  │
└───────────────────────┬───────────────────────┘
                        │ ops (batched)
┌───────────────────────▼───────────────────────┐
│ persist: IndexedDB = snapshot + op-log        │
└───────────────────────────────────────────────┘
```

## 3. Модель данных

```ts
type NodeId = string;            // nanoid, глобально уникален (задел под синк)

interface OutlineNode {
  id: NodeId;
  parent: NodeId | null;         // null только у невидимого root
  children: NodeId[];            // упорядочены по order
  order: string;                 // fractional index среди соседей
  text: string;                  // plain text, без разметки
  collapsed: boolean;
  tags: string[];                // кэш parseTags(text), lowercase
  created: number; updated: number;
}

class Doc {
  nodes: Map<NodeId, OutlineNode>;
  root: NodeId;
}
```

- **Невидимый root.** Все bullet'ы верхнего уровня — его дети. Тогда не нужны особые случаи «нет родителя». Второй скрытый корень — корзина `TRASH` (§7и): удалённые пункты живут там до компакции.
- **`children[]` в памяти + `order` на диске.** Массив даёт O(1) доступ к соседу и быстрый обход. Строка `order` (fractional indexing) позволяет вставить элемент между двумя соседями, не перенумеровывая остальных. Синхронизации это понадобится. `splice` в массиве даже на 10 тыс. детей — микросекунды.
- **Текст без разметки.** Теги, а в будущем ссылки и даты, — производные от текста и вычисляются парсером. Так проще хранение, undo и поиск.

## 4. Операции, команды, undo

**Ops** — атомарные и обратимые:

```ts
type Op =
  | { t: 'insert'; parent; node: NodeSnapshot }   // поддерево целиком
  | { t: 'remove'; parent; node: NodeSnapshot }   // снимок удаляемого поддерева
  | { t: 'setText'; id; from: string; to: string }
  | { t: 'move'; id; from: Position; to: Position }
  | { t: 'setCollapsed'; id; from: boolean; to: boolean };
```

Каждая операция несёт и старое, и новое состояние, поэтому `invert(op)` обходится без документа: `insert` ↔ `remove`, у остальных меняются местами `from` и `to`. `Doc.apply(op)` — единственное место, где меняется `Doc`. Если `from` не совпадает с текущим состоянием, операция отклоняется. Подписчики (`VisibleRows`, позже `TagIndex` и хранение) получают каждую операцию, а `transact()` объединяет пачку в один commit и при ошибке откатывает уже применённое.

**Commands** — пользовательские действия, каждое возвращает пачку ops (`Op[]`):

| Клавиша | Команда | Семантика (как в Workflowy) |
|---|---|---|
| Enter | `split` | Делит текст по позиции каретки. Каретка в начале → новый пустой bullet выше. Есть развёрнутые дети → новый bullet становится первым ребёнком |
| Backspace в начале | `mergeUp` | Пустой bullet удаляется. Непустой склеивается с предыдущей видимой строкой, если у текущего нет детей |
| Ctrl+Shift+Backspace | `delete` | Удалить bullet с поддеревом |
| Tab | `indent` | Стать последним ребёнком предыдущего соседа. Нет соседа выше → no-op |
| Shift+Tab | `outdent` | Стать следующим соседом родителя. Нижние соседи остаются у старого родителя |
| Alt+Shift+↑/↓ | `moveUp/Down` | Поменяться местами с соседом. На краю — перейти в конец/начало соседнего «кузена» |
| Ctrl+↑/↓ | `collapse/expand` | — |
| ↑/↓ | фокус | Переход на соседнюю видимую строку, когда каретка на первой/последней визуальной строке |
| Ctrl+Z / Ctrl+Shift+Z | undo/redo | — |
| Esc | — | Сбросить фильтр |

**История** (`src/model/history.ts`): стек пачек операций, до 1000 шагов, только на время сессии. Undo применяет обратную пачку в обратном порядке, redo — исходную. Каждая команда — один шаг. Набор текста (`Outliner.type`) склеивается в один шаг на слово: нажатия продлевают открытый шаг, пока пауза < 1 с и предыдущий текст не кончается пробелом. После undo/redo открытый шаг закрывается. Курсор после undo/redo: для правки текста — в конец изменённого участка, для команд — туда, где команда была вызвана (`before`) или куда она перевела фокус (`after`). Клавиши Ctrl/Cmd+Z, Ctrl/Cmd+Shift+Z и Ctrl/Cmd+Y распознаются по физической клавише (`e.code`), поэтому работают и в русской раскладке. Нативное undo contenteditable перехватывается через `beforeinput` (`historyUndo` / `historyRedo`).

**Многострочная вставка** — одна пачка операций, один шаг undo и одна запись на диск. Каждая строка становится отдельным bullet'ом. Типичный размер вставки — от нескольких до сотен строк. Отступы в тексте (табы, пробелы, `- `) пока не превращаются в вложенность.

## 5. Отрисовка: видимые строки и виртуализация

**VisibleRows** — плоский pre-order список `{id, depth}`. Корень не входит, свёрнутые поддеревья пропускаются, в режиме фильтра остаются только узлы из keep-set. В pre-order поддерево всегда занимает непрерывный отрезок, поэтому структурные операции обновляют список точечно:
- `create` / `delete` / `collapse` → `splice` одного отрезка;
- `indent` / `outdent` → меняется `depth` у отрезка (позиции те же);
- `move` → два отрезка меняются местами.

Полный пересчёт делаем при смене фильтра и при загрузке. Это O(видимых узлов), на 200 тыс. ≈ 5–10 мс.

**Виртуализатор пишем сам** (~200 строк), потому что фокус, каретка и скролл здесь — ядро продукта:
- Высоты строк разные (длинный текст переносится). Измеренные высоты кэшируются в `Map<id, px>`, для неизмеренных берётся оценка.
- Префиксные суммы высот хранятся в дереве Фенвика. И смещение строки, и строка по `scrollTop` находятся за O(log n). Изменение высоты одной строки — тоже O(log n).
- Высота измеряется через `ResizeObserver` на отрисованных строках.
- Якорь скролла: если меняется высота строки выше viewport, корректируем `scrollTop`, чтобы содержимое не прыгало.
- `scrollToRow(i)` нужен для фокуса при ↑/↓ и после команд.

**Строка (`Row`) работает в двух режимах:**
- **static** (все строки, кроме фокусной): обычный `<div>`, теги отрисованы как `<a class="tag">`. Клик по тегу → фильтр. Клик по тексту → фокус, позиция каретки из `document.caretPositionFromPoint`.
- **editing** (одна строка с фокусом): `<div contenteditable="plaintext-only">` с той же типографикой, поэтому вёрстка не прыгает. Инвариант — внутри ровно один text node, тогда смещение каретки = `Selection.anchorOffset`. На `input` читаем `textContent` и применяем `setText`. Источник истины на время набора — DOM, строку не перерисовываем, иначе прыгнет каретка. При blur строка возвращается в static, и теги подсвечиваются.
- Во время IME-композиции (`isComposing`) горячие клавиши не обрабатываются.

**Шрифт: только системный моноширинный, без веб-шрифтов.** `font-family: ui-monospace, monospace` (переменная `--font-text` в `src/index.css`):
- macOS/Safari: `ui-monospace` → SF Mono;
- Linux: `monospace` идёт через fontconfig (на этой машине это UbuntuMono Nerd Font, кириллица есть);
- Windows: шрифт берётся из настроек браузера (обычно Consolas).

Размер задан явно в px (`--font-size: 15px`). Без этого `monospace` упадёт до браузерных 13px. Отступ уровня — `--indent: 2ch`, то есть в «клетках» символов.

Моноширинный шрифт помогает виртуализатору: ширина строки в символах известна (`ширина колонки / 1ch`), поэтому высоту неизмеренной строки можно точно оценить как `ceil(длина / символов_в_строке) × line-height`. Скролл почти не прыгает.

**Оформление: компоновка Workflowy, палитра Claude.**
- **Компоновка:** тонкая шапка (название, поиск, переключатель темы) и одна центральная колонка шириной `--column: 80ch`. Bullet'ы — точки 6 px, свёрнутый bullet — с ореолом. Тонкие направляющие идут от точки каждого предка вниз через его детей: `.row::before`, повторяющийся градиент шириной в `--depth` уровней. Стрелка свернуть/развернуть появляется при наведении слева от bullet'а с детьми.
- **Цвета — из дизайн-системы Claude:**
  - светлая тема: кремовый холст `#faf9f5`, тёплый тёмный текст, бежевые линии;
  - тёмная тема: тёплый тёмный `#1f1e1b`, кремовый текст;
  - коралл `#cc785c` — фокус, каретка, выделение;
  - теги — коралловые ссылки (на креме темнее, `#a9583e`, ради контраста);
  - найденное — янтарная подсветка.
  Шрифты Claude лицензионные, поэтому шрифт по-прежнему системный моноширинный (см. выше). Знак Anthropic не используется.
- **Редизайн «зрелее и крупнее»** — по референсам Linear (структура ощущается, а не видна; глубина — шагами светлоты, а не тенями; акцент только для состояний), iA Writer (крупный моноширинный текст и колонка для чтения) и Tana (точка с ореолом = есть содержимое):
  - **Размеры.** Текст 17 px с интервалом 1,6, колонка 72ch, отступ уровня 2,5ch (на узком экране 16 px и 2ch). Шапка 64 px, поиск 44 px со скруглением 12 px, кнопки 40 px, заголовок zoom 34 px.
  - **Отклик.**
    - Редактируемая строка лежит на мягкой подложке `--surface`.
    - Теги и найденное — плашки.
    - Обе подложки нарисованы `box-shadow`-растяжкой и не сдвигают текст: начало редактирования не меняет вёрстку.
    - Точка под курсором увеличивается, «+» заливается кораллом.
    - У кнопок видимые кольца `:focus-visible`.
    - В поиске подсказка-клавиша `Ctrl F` / `⌘ F`.
  - **Один авторский момент движения:** смена темы раскрывается кругом от кнопки (View Transitions API, `TopBar.tsx`). При `prefers-reduced-motion` переключение мгновенное, все переходы обнуляются.
  - **Значки** — только нарисованные SVG одной толщины линии, никаких символов-заменителей.
  - **Виртуализатор** измеряет `--indent` пробником, а не предполагает его, потому что отступ зависит от ширины экрана.
- **Темы:** каждый цвет задан один раз через `light-dark(светлый, тёмный)` и выбирается по `color-scheme`. По умолчанию тема следует системной, кнопка в шапке выбирает явно (`data-theme` на `<html>`, `src/view/theme.ts`). Выбор запоминается в `localStorage` (если хранилище недоступно, выбор действует до перезагрузки), а скрипт в `index.html` применяет его до первой отрисовки, без мигания. Нативные элементы (полосы прокрутки, поля ввода) следуют той же `color-scheme`.

## 6. Реактивность (SolidJS)

- `rowsVersion: Signal<number>` — увеличивается при изменении VisibleRows. На него подписан только виртуализатор.
- `nodeSignal(id)` — сигналы по узлам, создаются лениво и только для отрисованных строк. `applyOp` дёргает сигнал изменённого узла. Перерисовывается одна строка, остальное не трогается.
- `focus: Signal<{id, caret}>`, `filter: Signal<FilterState | null>`.
- Сам `Doc` нереактивный, и его можно тестировать без DOM.

## 7. Теги и фильтрация (главная фича)

**Парсинг** (`src/model/tags.ts`): `/(?<=^|[\s(])#([\p{L}\p{N}_]+(?:-[\p{L}\p{N}_]+)*)/gu`. Тег начинается в начале текста или после пробела / «(», состоит из букв и цифр любого алфавита и `_`, внутри может быть дефис (`#война-и-мир`). Регистр приводится к нижнему (`#Пьер` == `#пьер`). `a#b`, `#`, `##` — не теги.

**Индекс:** `TagIndex = Map<tag, Set<NodeId>>`.
- `setText` → `parseTags(new)` → разница со старым `node.tags` → добавить/убрать id в нужных `Set`. Стоимость — O(длина текста одного bullet'а).
- `create` / `delete` — так же, по всем узлам поддерева.
- При загрузке индекс строится одним проходом: 200 тыс. bullet'ов и 9 млн знаков — 54 мс. Тексты без `#` регулярка не трогает.

**Применение фильтра `#tag`:**
1. `matches = TagIndex.get(tag)`, k узлов, O(1).
2. **keep-set** = matches ∪ все их предки. Поднимаемся по `parent` и останавливаемся, как только встретили узел, который уже в наборе. Итого O(размер keep-set), а не O(k·глубина).
3. VisibleRows строится обходом от root (`Filter = { keep, open }` в `src/model/rows.ts`). Узел из keep показывает только детей из keep — путь к совпадениям. Совпавшие узлы поэтому **свёрнуты** (как в Workflowy), а у узла пути с другими детьми есть кружок «есть скрытое». Клик по bullet'у или Ctrl+↓ добавляет узел в `open`, и тогда видны все его дети, а ниже работает обычное `collapsed`. Раскрытие в фильтре временное: оно не меняет `node.collapsed`, не попадает в историю и на диск.
4. Виртуализатор рисует первый экран.

Размер всего документа на стоимость **не влияет**, важно только, сколько найдено. Замер (Chromium, 200 тыс. bullet'ов, 9 млн знаков, тег на ~3300 bullet'ах, ~4900 строк с путями): keep-set 2–3 мс, строки 4–10 мс, от клика до отрисованного кадра 22 мс. Сброс фильтра пересобирает все 200 тыс. строк — 20 мс.

**Правка в режиме фильтра.** Изменение текста строки не меняет: если стереть тег у bullet'а, он не исчезает из-под каретки. Вставленные и перемещённые bullet'ы остаются видимыми (`VisibleRows.admit`): если родитель показывает только путь, узел добавляется в keep и open, а его скрытые предки — в keep. Например, Tab под скрытого соседа проявляет этого соседа. Повторный клик по тегу пересчитывает выборку с нуля. Рандомизированный тест проверяет, что после любой команды под фильтром строки совпадают с полной пересборкой и что bullet, куда команда ставит каретку, виден.

**Интерфейс.** Клик по тегу в любой строке включает фильтр (редактирование при этом выходит). Сверху панель: тег, число bullet'ов, «× сбросить (Esc)». Esc сбрасывает фильтр: если строка редактировалась, редактирование продолжается уже в полном документе и прокручивается к ней. Следующий Esc выходит из редактирования. Новый фильтр показывает результат с начала.

**Несколько тегов** в запросе (`#a #b`) — пересечение `Set`, начиная с самого маленького. `OR` — объединение по альтернативам, `-#тег` — разность; индекс тот же.

## 7а. Поиск по тексту

Поиск и фильтр по тегу — один механизм: строка поиска вверху, клик по тегу подставляет в неё `#тег`, а результат показывается тем же фильтром (совпадения с путём, правка прямо в результатах, §7).

**Запрос** (`src/model/search.ts`, `parseQuery`):
- слова через пробел должны **все** встретиться в одном bullet'е;
- `"фраза в кавычках"` ищется целиком, `#тег` берётся из TagIndex;
- `-слово`, `-"фраза"`, `-#тег` исключают;
- `is:done` и `-is:done` оставляют только выполненные или только невыполненные;
- `OR` (или `ИЛИ`, `|`) разделяет альтернативы (`Clause`): пункт подходит, если подходит любая из них;
- запрос из одних исключений означает «всё, кроме».

Подсвечиваются только искомые слова, не исключённые. Сравнение без учёта регистра, «ё» = «е» (`normalize` сохраняет длину текста, поэтому найденные смещения годятся для подсветки). Регулярных выражений в запросе пока нет.

**Индекс** (`TextIndex`): нормализованная копия текста каждого bullet'а, обновляется по ops так же, как TagIndex. Поиск — один проход `includes` по готовым строкам, без перевода в нижний регистр на каждый запрос. Если в запросе есть тег, перебираются только bullet'ы с этим тегом. Копия строится лениво: кусками по ~1000 bullet'ов, пока браузер простаивает (`requestIdleCallback` с проверкой `timeRemaining`). Если поиск пришёл раньше, он достраивает остаток сам. Так её построение (131 мс на 200 тыс. bullet'ов) не добавляется к загрузке и не блокирует ввод одним куском. Память: ещё одна копия текстов, ~18 МБ на 9 млн знаков кириллицы.

**Интерфейс:** Ctrl/Cmd+F переводит курсор в строку поиска (встроенный поиск браузера не видит виртуализированные строки). Поиск идёт по мере набора, не чаще раза за кадр. Совпадения подсвечиваются (`decorate`), справа число найденных bullet'ов. Enter или ↓ — редактировать первое совпадение. Esc в строке поиска сбрасывает поиск, Esc в редактируемой строке тоже сбрасывает поиск, а редактирование продолжается в полном документе.

**Замеры** (Chromium 152, 200 тыс. bullet'ов, 9 млн знаков; поиск — вычисление совпадений, строки — keep-set и пересборка списка):

| Запрос | Совпадений | Поиск | Строки |
|---|---|---|---|
| `наташа смотрел` | 6 560 | 23 мс | 13 мс |
| `бородино` | 27 992 | 19 мс | 25 мс |
| `"тихо быстро"` | 705 | 19 мс | 5 мс |
| `#война кутузов` | 474 | 3 мс | 2 мс |
| `а` (почти всё) | 181 585 | 20 мс | 69 мс |

От нажатия до отрисованного результата (e2e, через секунду после загрузки) — 48–58 мс, включая ожидание кадра. Если искать в первую же секунду после загрузки, первый поиск может дополнительно достраивать индекс, до +130 мс. Если когда-нибудь полный проход станет узким местом, следующие шаги — триграммный индекс или перенос поиска в Web Worker.

## 7б. Zoom в bullet

Как в Workflowy: клик по точке bullet'а или Alt+→ делает его заголовком страницы, а его детей — верхним уровнем. Над заголовком «хлебные крошки» (`Главная › …`), Alt+← или крошка выходит на уровень вверх, и курсор встаёт на bullet, из которого вышли. Свернуть/развернуть теперь — стрелка слева от bullet'а (видна при наведении) и Ctrl+↑/↓.

- **Модель:** `VisibleRows.top` — чьи дети показаны на глубине 0 (корень или bullet, в который вошли). `setTop` пересобирает строки. Операции вне поддерева `top` строк не трогают (`contains`). Сам `top` показывает детей независимо от своего `collapsed`.
- **Команды не выводят строку за пределы zoom:** Shift+Tab и перемещения на верхнем уровне останавливаются на `rows.top`. Enter в заголовке создаёт первого ребёнка (`prependChild`).
- **Поиск и теги внутри zoom** ищут только в его поддереве. `keepSet` строится от `top`, поэтому пустой результат — пустой экран.
- **Адрес:** zoom хранится в адресе как `#/<id>` (`src/view/zoom-hash.ts`). «Назад» и «вперёд» браузера выходят и входят, перезагрузка сохраняет место. Адрес, не указывающий на существующий bullet, отбрасывается без новой записи в истории.
- **Логотип «Listik»** в шапке — «домой»: выход из zoom, сброс поиска, прокрутка к началу и сворачивание всех пунктов верхнего уровня, у которых есть дети (`collapseChildren`, глубже ничего не трогается). Сворачивание — часть документа и один шаг отмены. На 200 тыс. bullet'ов (~700 глав) — 17–24 мс до кадра.
- **Кнопка «+»** под списком в zoom (как в Workflowy) добавляет пустой bullet последним ребёнком (`appendChild`) и ставит в него курсор: список можно наполнять без клавиатуры. Один клик — один шаг отмены. Во время поиска кнопка скрыта. Список виртуализирован, поэтому кнопка позиционируется не в потоке строк, а по их суммарной высоте (`total`), и высота области прокрутки учитывает её строку.
- **Заголовок** (`ZoomHeader.tsx`) редактируется как строка: набор идёт через `o.type`, работают undo и Esc. ↓ переходит к первому ребёнку.
- **Удаление:** если удалить bullet, внутри которого вы находитесь (или отменить его создание), zoom выходит на главную.
- **Сигналы узлов** теперь со счётчиком ссылок (`acquire` / `release`): один bullet могут одновременно показывать заголовок, крошки и строка.

Рандомизированный тест правит документ внутри zoom: строки совпадают с полной пересборкой, всё видимое лежит внутри, bullet'ы снаружи не сдвигаются.

## 7в. Экспорт, импорт, резервные копии

Документ живёт в IndexedDB одного браузера, поэтому выгрузка в файл — главная страховка.

- **Форматы** (`src/model/outline-text.ts`):
  - Markdown: `- текст`, 2 пробела на уровень;
  - OPML 2.0: формат обмена Workflowy и других outliner'ов, со спецсимволами XML.

  Оба формата читаются обратно.
- **Разбор текста с отступами** (`parseIndented`):
  - вложенность определяется только относительным отступом, пробелами или табами (таб = 4);
  - маркеры `-` `*` `+` `•` `1.` и знаки заголовков `# ` отбрасываются, `#тег` остаётся;
  - пустые строки пропускаются.

  Так читаются и Markdown, и текстовый экспорт Workflowy, и просто текст с отступами.
- **Импорт** (меню «⋯» → «Импорт из файла…») добавляет пункты последними детьми текущего уровня: корня или bullet'а, в котором вы находитесь (`appendTrees`). Каждое дерево вставляется одной операцией `insert` с поддеревом, и весь импорт — один шаг отмены.
- **Вставка нескольких строк** строит дерево (`insertTrees`): текст первой строки встаёт на место курсора, её дети становятся первыми детьми текущего bullet'а, остальные деревья идут ниже, а хвост текста после курсора переходит в конец последнего.
- **Автокопия в папку** (`src/persist/backup.ts`, Chrome и Edge, File System Access API):
  - вы выбираете папку, дескриптор хранится в `meta`/`backupDir`;
  - при изменениях документ пишется в `listik-ГГГГ-ММ-ДД.md` не чаще раза в 5 минут и при уходе со вкладки;
  - один файл на день, так что в папке копится история по дням.
  
  После перезагрузки браузер обычно снова спрашивает разрешение: тогда в меню «Автокопия на паузе — продолжить», нужен клик. Ошибки записи показываются там же («повторить»).

## 7д. Задачи (чекбоксы) и заметки

- **Модель.** У узла есть `todo` (задача, рисуется чекбоксом) и `done` (выполнена). Выполненной может быть только задача, обычный пункт — просто текст. Операции: `setTodo`, `setDone`, `setNote` (последняя с `at`, как `setText`). Формат снимка v3 добавляет `todo`. Снимки v1/v2 читаются, а в v2 всё выполненное и было задачей, поэтому выполненное становится выполненной задачей.
- **Ctrl/Cmd+Enter** (`cycleTask`): обычный пункт становится задачей — пустым чекбоксом; у задачи отметка ставится или снимается. На нескольких пунктах сначала все обычные становятся задачами, потом отмечаются все разом.
- **Ctrl/Cmd+Shift+Enter** (`untask`) — задача снова становится обычным пунктом.
- **Клик по чекбоксу** без сдвига мыши ставит или снимает отметку, редактирование строки при этом продолжается. Клик по точке обычного пункта по-прежнему ведёт внутрь (zoom), перетаскивание работает за оба вида.
- **Отсечка по задачам.** Ctrl+O скрывает выполненные задачи. В поиске `is:done`, `is:todo` (открытые) и `is:task` (все задачи), с отрицанием через `-`.
- **Заметка:**
  - Shift+Enter переходит из текста в заметку и обратно, Esc из заметки тоже возвращает в текст;
  - ↓ с последней строки текста ведёт в заметку, ↑ с первой строки заметки — в текст;
  - Enter в заметке — новая строка;
  - набор в заметке группируется в шаги отмены так же, как в тексте.
- **Перевод строки в заметке.** Chromium вставляет `\n\n`: второй перевод — заглушка, чтобы пустая последняя строка была видна. Поэтому DOM заметки не переписывается: модель хранит текст без одной завершающей `\n`, а при записи извне заглушка добавляется обратно.
- **Скрыть выполненные** (Ctrl+O или меню, настройка запоминается в браузере). `VisibleRows.setHideDone` отбрасывает выполненных детей в `shownChildren`, поддерево уходит вместе с ними. Отметка «сделано» при скрытии точечно убирает строку, снятие отметки возвращает её; массовая отметка пересобирает список один раз. Если строка с курсором исчезла, курсор переходит на строку, вставшую на её место. Рандомизированный тест сверяет строки с полной пересборкой.
- **Теги и поиск читают текст вместе с заметкой** (`content` в `tags.ts`). Backspace не склеивает пункт с заметкой, чтобы её не потерять.
- **В файлах:**
  - Markdown: задачи — `- [ ] пункт` и `- [x] пункт`; строки заметки — без маркера, с отступом на уровне текста;
  - OPML: атрибуты Workflowy `_complete` и `_note`, наш `_task="true"` для задачи; переводы строк кодируются как `&#10;`.

## 7е. Выделение нескольких пунктов

- **Как выделить:**
  - Shift+↑/↓ на крайней строке текста — этот пункт и соседний;
  - Shift+клик — диапазон от редактируемого (или уже выделенного) пункта.
- **Что выделено** (`Outliner.selection = { anchor, head }`): видимые строки между anchor и head, расширенные до целых поддеревьев. Набор и «корни» (выделенные, чей родитель не выделен) кэшируются по версии строк.
- **Клавиши** (`onSelectionKeys`), каждая команда — один шаг отмены:
  - Shift+↑/↓ — двигать head;
  - Tab / Shift+Tab — вложить / вынести блок (`indentMany`; если первый пункт вложить некуда, блок не двигается — иначе он развалился бы);
  - Alt/Ctrl+Shift+↑/↓ — переместить блок целиком (не дальше краёв и zoom);
  - Ctrl+Enter — сделано;
  - Backspace / Delete — удалить;
  - Ctrl+C / Ctrl+X — скопировать / вырезать как Markdown (`markdownOf`);
  - Ctrl+A — всё видимое.

  Esc, Enter, стрелка без Shift или клик снимают выделение.

## 7ж. Перетаскивание

Тянуть можно за точку bullet'а (`src/view/drag.ts`). Если мышь сдвинулась меньше чем на 4 px, это клик, и он ведёт внутрь пункта (zoom). Иначе начинается перетаскивание:
- тянется сам пункт с поддеревом или, если он в выделении, всё выделенное;
- перетаскиваемые строки приглушены;
- коралловая линия показывает место и уровень. Уровень следует за x указателя в допустимых пределах: не мельче следующей строки и не глубже ребёнка предыдущей.

Бросить пункт между строками перетаскиваемого блока или внутрь его поддерева нельзя. Esc отменяет перетаскивание, у края списка он сам прокручивается.

Модель — `moveManyTo(ids, parent, after)`, один шаг отмены. Новые ключи порядка лежат строго между двумя соседними ключами, которые существуют сейчас, поэтому не могут совпасть с ключом перемещаемого пункта, который ещё не переехал. Если бросить «после самого себя», точкой отсчёта становится ближайший неперемещаемый предшественник.

## 7з. Справка по клавишам

`?` (когда ничего не редактируется), Ctrl/Cmd+/ в любом месте или пункт меню открывают панель с клавишами, сгруппированными по задачам: правка, структура, переходы, поиск, выделение (`src/view/Shortcuts.tsx`). Это нативный `<dialog>`: Esc и клик мимо закрывают его, фокус возвращается на место. На Mac показываются ⌘ и ⌥.

## 7г. Приложение без сервера (PWA)

`npm run app` собирает Listik и запускает его на `http://127.0.0.1:4173`. Один раз открыть этот адрес и установить: в Chrome — значок «Установить» в адресной строке. Дальше Listik открывается отдельным окном, без запущенного сервера и без интернета.

- **Манифест** `public/manifest.webmanifest`: имя, `display: standalone`, значки 192/512, maskable и SVG. Значки рисуются из `public/icons/icon.svg` (`magick`).
- **Service worker** `public/sw.js`, регистрируется только в сборке, чтобы в разработке кэш не подменял dev-сервер:
  - страница идёт сначала из сети, поэтому новая сборка приходит при следующем открытии, а без сети берётся из кэша;
  - файлы сборки с хэшем в имени берутся сначала из кэша, потому что их содержимое никогда не меняется.
- **Данные привязаны к адресу.** У dev-сервера (`:5173`) и приложения (`:4173`) разные IndexedDB. Перенести документ между ними можно экспортом и импортом (§7в).
- **e2e:** Playwright-проект `pwa` поднимает `vite build` + `vite preview`, проверяет манифест и контроль service worker'а, затем отключает сеть и перезагружает страницу: приложение открывается вместе с данными.

## 7и. Корзина, общие ключи порядка, часы

Три изменения модели ради синхронизации; все они нужны и без неё.

- **Корзина.** У `Doc` два корня: `root` и скрытый `TRASH`. Удаление пункта (Backspace, Ctrl+Shift+Backspace, удаление выделения, отмена создания — `invert(insert)`) — это `move` в корзину, а не `remove`. Ключ порядка в корзине — время удаления в base‑36 (`trashKey`), поэтому корзина отсортирована по возрасту. Так правка с другого устройства, пришедшая к уже удалённому пункту, применяется в корзине и не теряется, а отмена удаления работает между устройствами. Компакция (`purgeTrash`) уничтожает записи старше 30 дней; чистка локальна и не синхронизируется: операция о вычищенном пункте просто отбрасывается. `VisibleRows` корзину не видит (она не под `root`), `TagIndex` и `TextIndex` исключают её: при `move` через границу корзины поддерево входит в индексы или покидает их. Снимок v4 хранит строки корзины после строк документа (`parent = -2`).
- **Общие ключи порядка.** Два устройства, вставившие пункты в одну щель, дают одинаковый дробный ключ. Дети отсортированы по паре (`order`, `id`), равные ключи допустимы, а `Doc.ordersAt` при равных соседях ставит новые ключи после всей серии равных (между равными ключами ничего нет).
- **Часы.** `clock.ts` — гибридные логические часы: монотонные миллисекунды, которые не повторяются на устройстве и перепрыгивают вперёд любую метку, увиденную с другого устройства. `at` у `setText`/`setNote` и `created` берутся из них; по ним решается, чья правка позже.

## 7к. Синхронизация между устройствами

Один пользователь, много устройств, работа без сети. Сервер (`server/index.js`) — упорядоченный журнал **зашифрованных** пачек операций на документ плюс последний зашифрованный снимок и слот ключа; он не понимает содержимого. Слияние целиком на клиенте.

**Протокол** (`src/sync/client.ts`, `engine.ts`):
- Устройство применяет серверный журнал по порядку и запоминает `head` — последний применённый номер. Локальные операции копятся в **outbox** (в `meta`, переживает перезагрузку) и уходят одной пачкой через ~1 с после правки. `setCollapsed` не отправляется: свёрнутость — состояние просмотра устройства.
- **Compare‑and‑append.** Пачка отправляется с `parent = head`; если кто‑то успел раньше, сервер отвечает 409, устройство подтягивает новое, перебазирует и повторяет.
- **Перебазирование.** В одной транзакции: откатить outbox (через `invert`), применить чужие операции, заново наложить outbox — всё через `applyMerged` (ниже). Отправляется outbox как был написан: все устройства прогоняют одну и ту же детерминированную функцию слияния над одним порядком, поэтому сходятся.
- **Цепочка хэшей.** Внутри шифротекста пачки лежит `prev` — SHA‑256 предыдущей пачки. Пачка, которая не расшифровывается или не продолжает цепочку, останавливает синхронизацию с ошибкой: сервер подменил, переставил или потерял записи. AAD шифрования включает код документа и номер пачки, поэтому пачку нельзя переставить на другое место.
- **Снимки.** Раз в 500 пачек (и при создании документа — снимок с номером 0) устройство с пустым outbox выгружает зашифрованный `gzip(serialize(doc))` с номером `head` и хэшем цепочки. Новое устройство (`bootstrap`) начинает со снимка и читает журнал после него. Сервер удаляет пачки, вошедшие в снимок, через `LISTIK_RETENTION` дней; устройство, отставшее дальше, получает 410 и загружает документ заново со снимка, сохранив outbox.
- **Живые обновления.** Поток `GET /events` (fetch со streaming, не EventSource, чтобы передать заголовок авторизации) сообщает новый `head`; плюс подтягивание при возвращении вкладки и при появлении сети.

**Доступ.** Создание документа — первый `PUT keyslot` с токеном; `LISTIK_ALLOW_CREATE=0` закрывает его, не трогая существующие документы и подключение к ним. Неудачные авторизации и обращения к несуществующим документам ограничены: 20 за 10 минут с адреса, дальше 429. Код документа (20 случайных знаков) и токен (32 байта из Argon2id) перебором не берутся; ограничение защищает от шума и диска.

**Слияние** (`src/model/merge.ts`, `merge-text.ts`). `Doc.apply` строг: операция с устаревшим `from` отклоняется. Поэтому чужая операция (и undo, если пункт с тех пор менялся) проходит через `applyMerged`, который превращает её в операции, выполнимые на текущем документе:
- поля независимы: перемещение и правка одного пункта оба применяются;
- текст и заметка сливаются трёхсторонне (`merge3` по `from`/`to` операции и текущему тексту, разность через `fast-diff`); если правки задевают одни и те же слова, побеждает более поздняя по часам, а проигравшая версия дописывается в заметку с пометкой `⚠ Другая версия`;
- `insert` существующего пункта — перемещение; `insert` под отсутствующего родителя — в корзину; `remove` с другого устройства — в корзину;
- `move`, создающий цикл, пропускается; `move` пункта, который уже не там, где ожидалось, всё равно выполняется (его устройство двигало нарочно);
- `setTodo`/`setDone` применяются, если значение отличается; `setCollapsed` чужой — никогда не приходит.

Тесты (`tests/sync.test.ts`) гоняют настоящий сервер в процессе: три устройства случайно правят, отменяют и синхронизируются вразнобой, в конце сходятся побайтно (без учёта свёрнутости); отдельно — конфликт одного текста, снимок и retention, подделанная пачка.

## 7л. Шифрование

Сквозное: сервер и локальная IndexedDB хранят только шифротекст (`src/sync/crypto.ts`, `src/persist/codec.ts`).

- **Ключи.** Пароль + код документа (случайный, он же соль) → Argon2id (64 МиБ, 3 прохода, `hash-wasm`) → **KEK**. KEK заворачивает случайный **ключ документа (DEK)** в слот ключа, который лежит на сервере и локально; смена пароля — перезаворачивание без перешифровки. Из KEK же выводится (HKDF) **токен** для сервера: сервер знает только его SHA‑256 и может отказать или испортить, но не прочитать. Из DEK выводится ключ данных AES‑256‑GCM.
- **Записи.** Кодек хранилища пишет снимок и пачки журнала как `{enc: 1, iv, ct}`; шифрованный кодек читает и старые открытые записи, поэтому включение шифрования — одна принудительная компакция (Worker получает `CryptoKey` через structured clone). Открытый кодек на шифрованной записи бросает `LockedError`.
- **Устройство.** «Запомнить на этом устройстве» — неизвлекаемый `CryptoKey` в IndexedDB запечатывает DEK и токен; иначе пароль спрашивается при каждой загрузке (`Unlock.tsx`). Это защищает данные на диске, но не от кода, выполняющегося в странице.
- **Доверие к коду.** Приложение раздаётся с GitHub Pages, данные лежат на своём сервере: взлом одного места не даёт одновременно подменить код и прочитать данные. Если раздавать и то и другое с одного сервера, подмена кода остаётся вне модели угроз.

Пока синхронизация не включена, документ хранится открыто, как раньше: пароля нет.

## 8. Хранение (IndexedDB)

**Схема: snapshot + журнал операций.**
- `meta/snapshot` — одна запись со всем документом в pre-order: `[id, parentIdx, order, text, collapsed, created, updated][]`. Pre-order означает, что дети приходят по порядку и сортировать при загрузке не нужно. Для 5 млн знаков ≈ 7–8 МБ JSON, `JSON.parse` ≈ 30–60 мс.
- `oplog` — пачки ops с автоинкрементным ключом, накопленные после snapshot.

**Запись** (`src/persist/idb.ts`): ops копятся в памяти и сбрасываются одной транзакцией через 300 мс после первого, а также на `visibilitychange: hidden` / `pagehide`. Подряд идущие `setText` одного bullet'а схлопываются в одну операцию. Стоимость сохранения правки не зависит от размера документа. При аварии теряется не больше последних 300 мс.
**Компакция** (с M4, `src/persist/compact.ts` в `compact.worker.ts`): когда в журнале > 10 000 ops, Web Worker в одной транзакции читает снимок и журнал до последнего ключа K, применяет журнал, затем в другой транзакции пишет новый снимок и удаляет записи с ключами ≤ K. Главный поток только дописывает журнал. Записи, добавленные во время компакции, получают ключи > K, остаются в журнале и применяются поверх нового снимка, поэтому счётчик поколений из M2 больше не нужен. Без Worker (unit-тесты в Node) та же функция работает в процессе. Рандомизированный тест правит документ, пока идут компакции; мутационная проверка (удалять весь журнал вместо ≤ K) этим тестом ловится.
**Загрузка:** читаем snapshot (прямое заполнение `Map`, без ops), применяем журнал, строим VisibleRows. Если операция журнала не применяется, загрузка падает с ошибкой, а данные в базе остаются нетронутыми. Молча отбрасывать хвост журнала нельзя.
**Защита от вытеснения:** `navigator.storage.persist()`.
**Параметры URL:** `?db=имя` — выбрать базу (тесты, бенчмарк). `?demo` и `?sample=N` — документы только в памяти, сохранённые данные они не трогают.

**Замеры M2** (Chromium 152, 200 тыс. bullet'ов, 9 млн знаков — втрое больше «Войны и мира»):

| Операция | Время |
|---|---|
| Загрузка (snapshot + журнал) | 343 мс |
| Применить правку | 0,2 мс |
| Сохранить одну правку | 1 мс |
| Компакция (сериализация 154 мс + запись) | 456 мс, блокирует main thread (в M4 перенесена в Worker: пауза 4–5 мс) |

Резерв на будущее: снимок без UUID-подобных id и с временем в секундах. 26 млн символов JSON на 9 млн знаков текста — в основном служебные поля.

**Одна пишущая вкладка** (`src/persist/lock.ts`). Вкладка, первой получившая Web Lock `listik:<база>`, держит его всю свою жизнь и одна пишет в базу. Остальные вкладки с тем же документом:
- читают его без записи (`Persistence.read`);
- показывают плашку «только просмотр»;
- не дают ничего менять: `Outliner.readOnly` блокирует команды, набор и undo, а строки и заголовок не становятся редактируемыми;
- не показывают «+», импорт и автокопию.

Экспорт, поиск и zoom работают. Когда пишущая вкладка закрывается, ожидающий запрос блокировки срабатывает, и вкладка перезагружается уже как пишущая. Это безопасно: в режиме просмотра нечего терять. Без Web Locks (очень старые браузеры) пишут все вкладки, как раньше.

Почему не по записи на узел: `getAll()` на 200 тыс. записей — это секунды на холодном старте, плюс тысячи мелких записей. Почему не SQLite-WASM/OPFS: +1 МБ wasm и сложная настройка ради FTS, который в MVP не нужен. Если понадобится, вернёмся к этому вместе с поиском.

## 9. Масштаб и запасные ходы

- Если 1 млн узлов не поместится в бюджет памяти: struct-of-arrays (целочисленные индексы, `Int32Array` для parent/firstChild/nextSibling, тексты в отдельном массиве строк). API `Doc` при этом не меняется.
- Память: ~450 байт на bullet (91 МБ на 200 тыс.). Около 1 млн bullet'ов это уже ~450 МБ, и тогда понадобится struct-of-arrays (выше). Мелкие резервы (общий пустой `children[]` у листьев, компактные метки времени) дают по 3–5 МБ и не стоят тонких инвариантов в ядре.
- Если загрузка станет узким местом: разбирать снимок в Worker и передавать главному потоку уже готовые колонки (typed arrays).
- Синхронизация сделана (§7к): журнал на сервере, перебазирование и слияние на клиенте. Если документ дорастёт до того, что снимок станет тяжёл для выгрузки с телефона, снимки можно делать реже или в Worker.

**Массовые транзакции.** Если транзакция содержит больше `PATCH_LIMIT` = 16 операций (сворачивание сотен пунктов, длинная вставка, отмена таких команд), `VisibleRows` перестаёт патчить по одной и один раз пересобирает список на commit (и после отката). Команда, которая заранее знает, что операций будет много, вызывает `rows.expectMany()` (`collapseChildren`, `insertText`). Тогда точечных патчей нет вовсе: каждый из них на 200 тыс. строк стоит ~2 мс из-за пересборки раскладки виртуализатора. Под фильтром режим не включается — там патчи нужны, чтобы правленые строки оставались видимыми. Команды читают строки только до своих первых операций, поэтому устаревший список посреди транзакции они не видят.

**Заметки по M1:**
- `VisibleRows` сообщает подписчикам о каждом splice (`RowsListener`). Виртуализатор держит массив высот параллельно строкам и после структурной операции перестраивает дерево Фенвика за O(n), на 200 тыс. строк это ~1 мс. Замер высоты одной строки стоит O(log n).
- Фокус хранится как состояние (`Outliner.focus`), а не как DOM-фокус. Строка в фокусе рендерится как `Editable`, а при прокрутке назад монтируется заново и снова получает фокус. Потеря DOM-фокуса фокус не сбрасывает. Сбрасывают его Esc и скрытие строки (свернули родителя).
- Нативный undo в contenteditable заблокирован до M2: он рассинхронизировал бы DOM и модель.
- `insertText` (вставка из буфера) добавляет строки по одной, это O(k·n) для k строк в документе из n строк. Для реальных вставок (до сотен строк) этого достаточно. Массовый импорт не входит в сценарий (§1), и бенчмарк M4 строит документ сразу через `insert` поддеревьев (`src/dev/sample.ts`).

## 12. Известные риски

- **contenteditable** — главный источник багов: каретка, IME, вставка, Safari. Держимся инварианта «один text node» и `plaintext-only`. Нужны e2e-тесты (Playwright) на клавиатурные сценарии.
- **Переменная высота строк + виртуализация** — скачки скролла. Нужны якорь скролла и правильная оценка высоты, например по длине текста.
- **Вытеснение данных браузером** без `storage.persist()`. Экспорт в файл стоит сделать сразу после MVP.
- **Код из сети.** Веб-приложение не может защититься от подмены своего кода тем, кто контролирует его хостинг; поэтому код и данные разнесены (§7л). Забытый пароль синхронизации восстановить нельзя: ключ есть только у того, кто его знает.
- **Компакция пропускает чистку корзины между устройствами.** Чистка локальна; устройство, не выходившее на связь дольше 30 дней, может «воскресить» пункт из своей корзины правкой — он придёт как `insert` под отсутствующего родителя и ляжет в корзину получателя. Это видно только в корзине.
