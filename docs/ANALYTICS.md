# Аналитика использования

Цель — принимать решения о дизайне по реальным последовательностям: поиск → переход → правка → возврат; запись в Inbox; перемещение и работа с задачами. Считать отдельно телефон, планшет и ноутбук, а также касания, мышь/трекпад и клавиатуру.

## Хранение

Документ остаётся в своей IndexedDB: снимок и журнал операций проходят через codec и синхронизацию. Аналитика хранится отдельно в `listik-usage`, хранилище `events`, и в журнал документа не попадает. Сервер и другие устройства её не получают. На каждом устройстве собирается собственный журнал; JSON-файлы можно объединить по случайному идентификатору устройства. Установка PWA и отдельный браузер могут иметь разные хранилища.

Журнал содержит метаданные открытым текстом, но не содержимое документа: время, случайный ID устройства и сессии, платформу, ОС, размеры окна, действие, последний способ ввода и признак видимой экранной клавиатуры. Никакие названия заметок, идентификаторы нод, поисковые запросы, пароли или набранные символы не сохраняются. Размер ограничен последними 50 тысячами событий. Запись пакетами раз в секунду; при аварийном закрытии последняя секунда может потеряться. При ошибке хранилища редактирование продолжается, до 1000 событий ждут повторной записи в памяти.

Демо и нагрузочные документы не собирают аналитику.

## Разметка

Кнопки и поля имеют постоянные `data-action`. Исходное соответствие ID компонентам: `ACTION-CATALOG.json`. Номера — постоянные идентификаторы, при добавлении элементов существующие не перенумеровывать. Динамический набор панели клавиш дополнительно различается по фиксированным названиям команд `editbar.*`, без текста документа.

`action.*` — смысловые действия Outliner, в том числе поиск, навигация, ссылки, зеркала, задачи, удаление, восстановление, история. `key.*` — сочетания клавиш и служебные клавиши. Серия ввода сворачивается в одно событие после паузы 700 мс. Клики по точкам, раскрытию, тегам, чекбоксам и пути также фиксируются. Жест удаления/завершения отражается соответствующим смысловым действием. События жизненного цикла отмечают начало, скрытие и возвращение в приложение.

Клик, сочетание клавиш и вызванное ими смысловое действие — разные уровни одной операции, их нельзя складывать в общий счётчик действий. ID кнопки показывает вход, `action.*` — вызванное поведение. Вложенные вызовы также дают несколько смысловых событий. Автоматический переход в «Сегодня» при открытии может давать такое же событие, как ручной: для анализа смотреть предшествующий ввод и событие запуска.

## Платформа

Категория определяется по устройству и ОС, не текущей ширине окна. Узкое окно iPad остаётся планшетом; ноутбук с сенсорным экраном остаётся ноутбуком. Размеры окна сохраняются отдельно, поэтому можно отличить разделённый экран и изменение доступной области. Мышь и трекпад объединены браузером в `mouse`. Надёжного браузерного API для наличия внешней клавиатуры нет.

## Выгрузка и анализ

Меню документа → Файлы и резервные копии → Скачать аналитику использования. Файл содержит `schema` и `events`. Перед выгрузкой ожидается сохранение накопленных событий. При ошибке выдаётся сообщение вместо неполной выгрузки.

Через одну-две недели сравнить устройства: частоту входов в поиск и переходы; повторные поиски и короткие переходы с возвратом; долю клавиш, меню и панели правки; наиболее используемые действия; запись в Inbox и последующие перемещения. Время между событиями не равно активному времени работы: фоновые интервалы исключать, большие паузы отделять.

Это первая разметка поведения, без содержимого и связки с конкретной заметкой. Она покажет используемые маршруты и средства управления, но не сможет оценить релевантность найденного, восстановить точный путь нод или доказать успешность поиска. Для этих вопросов потребуется отдельная согласованная разметка результатов поиска. Будущие элементы интерфейса должны получать новый `data-action`.
