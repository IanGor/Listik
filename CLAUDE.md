# Listik — контекст для новой сессии

Outliner в стиле Workflowy: один бесконечный bullet-список. Главная цель — мгновенные фильтр по `#тегу` и поиск на документе объёмом «Войны и мира» и больше. Объём набирается **постепенно, внутри приложения** (массовая вставка — не сценарий): правка, фильтр, поиск, загрузка и сохранение должны оставаться быстрыми на таком размере.

Подробная архитектура, решения и замеры — **`docs/ARCHITECTURE.md`** (источник истины, обновлять вместе с кодом). Кто пользуется продуктом, зачем и чем он отличается — **`PRODUCT.md`** (для навыка дизайна `impeccable`; обновлять, когда меняется суть продукта). Нынешнее оформление (токены, компоненты, правила; направление переделки — TUI с анимациями) — **`DESIGN.md`** и `.impeccable/design.json`; обновлять вместе с изменениями вида. Последние цифры бенчмарка — `bench/RESULTS.md`. Пользовательская справка — `README.md`.

## Команды

```sh
npm run dev -- --host 127.0.0.1   # dev: http://127.0.0.1:5173 (/?demo, /?sample=200000, ?db=имя, &empty — новый документ без структуры)
npm run app                        # сборка + preview на :4173 (PWA, ставится как приложение)
npm test                           # Vitest (среда node; happy-dom только там, где указано в файле)
npm run test:e2e                   # Playwright: проекты app (dev :5180) и pwa (сборка :5181); сервер синхронизации на :5182
node server/index.js               # сервер синхронизации (LISTIK_DATA, LISTIK_PORT, LISTIK_ORIGINS, LISTIK_ALLOW_CREATE=0 после создания документа); деплой — server/DEPLOY.md
# Деплой: приложение — .github/workflows/pages.yml (каждый пуш в master); сервер — .github/workflows/server.yml (пуш с изменением server/index.js) → SSH listik-deploy → server/deploy.sh
npm run typecheck                  # tsc -b
npm run bench                      # бенчмарк 67k и 200k bullet'ов → bench/RESULTS.md (~3 мин)
```

- Используй **127.0.0.1**, а не localhost: на этой машине `::1` принимает соединение и зависает.
- Браузер — системный `/usr/bin/chromium` (Playwright без скачивания браузеров). Плагин chrome-devtools ищет Google Chrome и здесь не работает.
- Песочница Bash изолирует сеть между командами, поэтому сервер и браузер запускать в одной команде, а Playwright сам поднимает свои серверы.

## Словарь

- **Панель правки** (`EditBar.tsx`, `.editbar`) — полоса кнопок над экранной клавиатурой на сенсорном экране, пока пункт (или заголовок zoom и его заметка: `Outliner.titleEdit`, тогда один плоский набор `TITLE_MAIN`: заметка | жирный, курсив, время | отменить, повторить) редактируется. **Основной** набор (`ROW_MAIN`) — 9 кнопок по 44 px в четырёх группах через черту: вынести, вложить, «Переместить» | задача, заметка | `#` тег, `[[]]` ссылка | отменить, «Ещё». Открываемые им: **перемещение** (`move`: назад, вверх, вниз, «Куда…»; остаётся открытым; вынести и вложить — только в основном наборе) и **ещё** (`extra`: назад, `(( ))` зеркало, время, жирный, курсив, повторить, удалить). В наборах подпись под значком.
- **Структура** — семь пунктов верхнего уровня: «📥 Inbox», «PARA» с Projects, Areas, Resources, Archive внутри, «Kanban» с Backlog, `@q1`–`@q4` (кварталы-календарь), без заметок: создаётся при первом запуске нового документа (кроме `&empty`), при создании документа на сервере, если её нет, и всегда кнопкой меню «Создать структуру» (в конец).
- **Сегодня** (`Outliner.goToday`) — кнопка «Сегодня» в шапке и запуск без адреса места (не обновление страницы: оно оставляет место, поиск и прокрутку, `reload.ts`): zoom в день календаря (год создаётся при первом попадании), курсор не ставится. Любой вход в пустой день ставит шаблон (`Outliner.enterDay`). На главную ведёт крошка «Главная»; на главной она, как и последняя крошка в zoom, сворачивает первый уровень, а ещё раз — разворачивает (`goHome`, `toggleLevel`).
- **Крошки** (`Crumbs`) — путь над списком; **заголовок** (`ZoomTitle`) — текст пункта, в который вошли (zoom).
- **Подсказка** (`Suggest.tsx`) — список команд `/`, тегов `#`/`@` и пунктов для `[[ссылки` под курсором.
- **Ссылка** — `[[название]]` в тексте пункта; ведёт в первый по документу пункт с таким названием. Переименованный пункт уносит ссылки с собой: `Outliner.type` запоминает прежний текст (`retitled`), `settleTitle` при уходе курсора переписывает их (`relink`, один шаг отмены).
- **Зеркало / копии** — `((название))` делает пункт ещё одной копией другого. Все копии равноправны: ромбик у каждой (`Doc.isCopy`), текст, заметка, задача и поддерево общие, правка из любой. Внутри данные в одной копии (origin), остальные — пункты с `mirrorOf` без своих детей. Удаление копии убирает только её (origin передаёт всё следующей: `handOver`); одна оставшаяся — обычный пункт. Свёрнутость под каждым зеркалом своя (`VisibleRows.folds`, на устройстве).
- **Шаблон** (`templates.ts`) — пункт с `#template` со всем вложенным; `/template` вставляет копию содержимого без самого заголовка.
- **Строка мест** (`GoTo.tsx`, `Outliner.placeLine`) — строка посреди экрана над затемнённым списком. **Перейти к…** (Ctrl+K, только компьютер): название, Enter — zoom в первое место; пусто — недавние (`recentPlaces`). **Переместить в…** (Ctrl+Shift+M, «Куда…»): Enter кладёт пункты последними туда (`moveManyInto`), курсор остаётся на следующей строке; недавние цели — `recentTargets`. Поле поиска мест не показывает.
- **Быстрая запись** (`QuickCapture.tsx`) — одна строка «Мысль → Inbox» поверх списка; запись — в конец Inbox, курсор возвращается на место. Не «+»: «+» значит «добавить здесь».
- **Ключ строки** (`RowKey`) — адрес строки в списке: id пункта, а под зеркалом `ключ-зеркала/id`.

## Инварианты и подводные камни (важно не сломать)

- **Документ меняется только через `Doc.apply(op)`.** Каждая операция обратима (`invert`) и проверяет `from`, устаревшая — отклоняется. Команды применяют операции и возвращают `Focus`; `Outliner.run` оборачивает команду в `transact`, делает один шаг истории и переносит фокус. Сохранение — только запись операций в журнал. Операции **не с этого состояния** (с другого устройства, undo после чужих правок) идут через `applyMerged` (`merge.ts`), который детерминированно превращает их в применимые.
- **Зеркала.** Копии равноправны (§7н ARCHITECTURE): правка заголовка из любой копии идёт в origin; `remove` в `commands.ts` перед удалением зовёт `handOver` (origin в удаляемом поддереве передаёт текст, заметку, задачу, детей и ссылки первой оставшейся копии); `mergeUp` копии убирает только её, `blockOf` не берёт строки под выделенным зеркалом. Сворачивание под зеркалом — `VisibleRows.setFold` (не операция), там, где пункт лежит, — `setCollapsed` после `freeze`; рандомизированный тест сравнивает с пересборкой, получившей те же `foldEntries`. Команды содержимого (`setText`, `setNote`, `toggleDone`, `cycleTask`, `untask`, `insertTrees`, `Outliner.insert`/`format`) идут через `doc.content(id)`: view передаёт id строки, операция ложится на оригинал. Под зеркалом показываются дети оригинала, поэтому один пункт бывает в нескольких строках: строки, фокус, выделение, перетаскивание адресуются `RowKey` (`m/x`), команды берут пункт через `nodeOf`, дети под зеркало кладутся к оригиналу (`Doc.host`), строка, которую команда перенесла, — её возвращаемый ключ, новый пункт ищется `rows.locate(id, near)`. `VisibleRows` патчит каждую операцию во всех контекстах (`mirrors` — строки‑зеркала в списке); зеркало внутри того, что отражает, детей не показывает (`host`, проверка сегментов ключа). Рандомизированный тест зеркал — пять режимов строк (последний — фильтр в zoom через зеркала). `zoomTo` любого зеркала ведёт к `doc.origin`. Поиск: индексы видят только оригинал; `keepSet` добавляет к пути копии пунктов на нём, поиск в zoom оставляет совпадения, видимые через зеркало (`VisibleRows.reaches`, `shownRoots`), `admit` под фильтром поднимается до предка, у которого есть строка где угодно (`listed`). Снимок v5 (`mirror`). Экспорт пишет зеркало как копию.
- **`#secret`.** Пункт с `#secret` (текст или заметка) и всё внутри него не попадают ни в `TagIndex`, ни в `TextIndex` (§7у ARCHITECTURE), как корзина: поиск, фильтр, подсказки тегов, ссылки, зеркала и строка мест его не видят. Всё новое, что ищет пункты, берёт их из индексов, а мимо индексов (прямо по `doc.nodes`, недавние места, кэши) — проверяет `searchable`, а не `inOutline`. Шаблоны и календарь внутри секретного пункта не находятся.
- **Корзина.** Удаление — `move` в скрытый корень `TRASH` с ключом `deletedKey` = `trashKey(время)|order|parent` (прежнее место, для «Вернуть» в панели `Trash.tsx`); `invert(insert)` и слияние кладут туда с голым `trashKey` — в списке корзины их нет. `remove` остаётся только для `purgeTrash` при компакции (30 дней). Индексы тегов и текста корзину не видят, `VisibleRows` тоже. Дети сортируются по (`order`, `id`): равные ключи допустимы (параллельные вставки), `ordersAt` ставит новые после серии равных.
- **Синхронизация.** Сервер — упорядоченный журнал зашифрованных пачек; клиент применяет его по порядку, отправляет outbox с `parent = head` (409 → подтянуть, перебазировать через `applyMerged`, повторить), проверяет цепочку хэшей, раз в 500 пачек выгружает снимок. `setCollapsed` не синхронизируется. Новое устройство начинает со снимка (`bootstrap`): документ на сервере всегда создаётся со снимком № 0. Рандомизированный тест трёх устройств с настоящим сервером — `tests/sync.test.ts`; новое правило слияния — туда же.
- **Шифрование.** Включается вместе с синхронизацией: `Persistence.recode(encryptedCodec(key))` = принудительная компакция. Без синхронизации документ открытый. Пароль + код документа → Argon2id → KEK → токен сервера и обёртка DEK; «запомнить» = неизвлекаемый ключ устройства в `meta/device`. Экран пароля — `Unlock.tsx`, сценарии — `sync/setup.ts`. Смена кодека (`recode`) читает через `recoding(new, old)` и бросает при ошибке: иначе записи остаются под прежним ключом. Нечитаемая локальная копия → экран `Restore.tsx` («Загрузить с сервера»).
- **`doneAt`.** Каждая отметка задачи — через `commands.setDone` (несёт `at`: новый штамп или теряемый, чтобы `invert` вернул время); снимок v7 хранит `doneAt`. День входит с раскрытым `todo` (`zoomTo` после `collapseAll`).
- **`VisibleRows` патчится по каждой операции.** Если в транзакции больше 16 операций (`PATCH_LIMIT`) или команда вызвала `rows.expectMany()`, список пересобирается один раз на commit или rollback. Под фильтром патчи обязательны (`admit`: правленые и вставленные пункты не исчезают). `indexOf` ищет от последней найденной позиции. В commit `VisibleRows` подписан первым.
- **Рандомизированные тесты** сверяют инкрементальные строки с полной пересборкой: обычные правки, под фильтром, в zoom. Новый режим строк — новый такой тест. Есть защита от вырождения: проверяется число реально выполненных шагов.
- **Редактирование.** На время набора DOM — источник истины: строка не перерисовывается, текст из модели пишется в DOM только при изменениях извне. В тексте пункта одна text-нода. **Заметка** вне правки строки обрезана до 3 строк (`.note.clamped`, `NOTE_LINES` в оценке высоты), у zoom-узла видна целиком под заголовком (`TitleNoteEditable`). Chromium вставляет `\n\n` (вторая `\n` — заглушка для пустой последней строки), DOM заметки не переписывается, модель хранит текст без одной завершающей `\n`.
- **Сигналы узлов** (`NodeSignals`) ведут счёт ссылок: `acquire`/`release` на каждый компонент, который показывает узел.
- **Память.** V8 отдаёт длинные строки из `JSON.parse`, `slice` и `split` как срезы исходной строки, удерживая её целиком. При загрузке снимка и импорте строки копируются через `own()`: −50 МБ на 200k bullet'ов. При замерах памяти дать IndexedDB «остыть» и вызвать `gc()` дважды.
- **Пересборка снимка** работает в Worker: читает снимок и журнал до ключа K, удаляет записи ≤ K. Главный поток только дописывает журнал. Мутационная проверка (удалять весь журнал) рандомизированным тестом ловится.
- **Задачи.** `todo` — чекбокс; `done` бывает только у задач (снимок v2 мигрирует done → todo). Ctrl+L (⌘L, физическая клавиша `KeyL`; на телефоне — кнопка задачи) — `cycleTask` по кругу: задача → выполнена → обычный пункт; клик по чекбоксу — только отметка; Ctrl+Shift+L — `untask`; Ctrl+Enter ничего не делает. Клик по чекбоксу ставит отметку, клик по точке обычного пункта — zoom (`Outliner.pressBullet`). Любая отметка идёт через `Outliner.changeTasks`: выполненное через `SINK_DELAY` уходит последним к родителю (`sinkDone`), тост и Ctrl+Z возвращают.
- **Шапка `.topbar` закреплена (`sticky`) и непрозрачна**, у `html` фон холста: иначе iPadOS 26 размывает верх веб-приложения с экрана «Домой» (scroll edge effect). Полупрозрачность и `backdrop-filter` шапке не давать.
- **Наведение.** Каждое правило `:hover` — под `:where(:root.mouse)` (не утяжеляет правило; `screen.ts` `watchPointer`: класс, пока последним указателем была мышь или трекпад). `(hover: hover)` на iPad не выполняется даже с трекпадом Magic Keyboard (главный указатель — палец), а касание пальцем не должно оставлять подсветку. Поля ввода на сенсорном экране — не мельче 16 px (блок в конце `index.css`).
- **Цвета.** Задаются через CSS `light-dark()`, тема — `data-theme` на `<html>`, всегда вместе с системной (не сообщает — тёмная); выбор в меню держится до следующего переключения системы (`view/theme.ts`). Палитра Claude по `Reference/color_pallete.png`: холст `#faf9f5` / `#262624`, коралл (точки, фокус) `#c96442` / `#d97757`, жирное голубое, курсив зелёный (`--bold`, `--italic`), теги бирюзовые — дополнительный к кораллу, чтобы не сливались со ссылками (`--tag` `#28706a` / `#7cc2b8`, подложка `--tag-chip`). Новые цвета — только как токены в `:root` (`src/index.css`).
- **e2e:**
  - конец текста — `Control+End` (End ведёт в конец визуальной строки);
  - смена темы асинхронна (View Transitions), сначала ждать `data-theme`;
  - пороги времени на 200k — это проверки «не сломалось» с запасом, точные числа даёт `npm run bench`;
  - Ctrl+L делает пункт задачей, выполненной — второе нажатие, обычным — третье.
